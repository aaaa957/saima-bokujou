# 分崩点机制：实现、实测与一个反直觉发现（2026-10-05）

> 本文记录「末段集体掉速 / 分崩点」机制的**设计依据、实现、参数扫描结果**，
> 以及一个**推翻初始设计的实测结论**。**不宣称已拟合现实。**

---

## 一、现实中为什么会有「分崩点」

分崩点**不是一条规定距离的规则**，而是能量系统在末段自然收窄的结果。文献给出三条互相印证的原因：

| 来源 | 机制 |
|---|---|
| **Mercier & Aftalion 2020** | 比赛大部分时间马都在动用**无氧储备**维持高于有氧上限的配速；当**剩余无氧降到初值约 1/3** 时，可持续 V̇O₂ 开始下降 → 可用推进力下降 → 掉速 |
| **Langsetmo et al. 1997** | 高強度跑约 **136 s** 后叠加一个持续上升的 V̇O₂ **慢成分** ⇒ 同样速度的代价上升 |
| **Takahashi et al.**（步态） | 疲劳时"身体展不开"——对角步缩短 −19%、腾空步拉长 +7%，机械效率下降 |

### 为什么它落在「剩余距离」而不是「时间」上？

- 同一场比赛里所有马跑**同样的距离**，完赛时间只差几秒；
- 每米耗能对所有马**相近**；
- ⇒ 每匹马的储备会在**相近的剩余距离**处到达临界；
- ⇒ 集体掉速**自然涌现**，而不是因为有人规定"到 478 米就掉速"。

**Spence 自己提供了支持该解释的反证**：分崩点与**最后一个弯道的位置无关**
（Spearman ρ = −0.09，p = 0.43）。若是几何效应应当与弯道相关——它是**能量效应**。

---

## 二、为什么不能硬编码距离

一个粗暴的"到剩余 X 米就让全体减速"实现会有四个具体后果：

1. **不随条件变化**：现实中长距离赛的分崩点出现得更早、不同步速与地面也不同；硬编码在所有场景产生同一个点。
2. **抹掉个体差异**：现实中 **92%** 的马有这个模式 —— 也就是 **8% 没有**。硬编码会让 100% 的马在同一距离掉速，比赛变成齐步走。
3. **赢家逻辑会错**：现实是"**赢家是掉速最少的那个**"。若全体按同一曲线掉速，胜负只由进入分崩点时的位置决定。
4. **违背项目原则**：这正是"用机制外壳包装的调参"。

## 三、实现（`sim.js::raceSupplyState`）

**做法：让可持续有氧功率取决于这匹马自己的剩余储备比例，而不是距离。**

```js
const reserveRatio = clamp(H.stamina / H.staminaMax, 0, 1);
const endgame      = clamp(reserveRatio / RACE_F.anaerobicGate, 0, 1);
const aerobicTarget = H.aerobic * fatigue * (1 - (1 - endgame) * RACE_F.endgameFade);
```

新增两个参数（`RACE_F`）：

| 参数 | 值 | 含义 |
|---|---|---|
| `anaerobicGate` | **0.5** | 储备比例低于此值后开始衰减 |
| `endgameFade` | **0.40** | 衰减到底时可持续有氧功率的最大降幅 |

**性质**：每匹马各自在自己的储备临界处开始衰减 → 集体分崩是**涌现**结果；
储备更深的马衰减更晚 → 自然产生"赢家掉速最少"；长距离赛储备耗得更快 → 分崩点自然更早。

## 五、反直觉发现（本轮最重要）

**初版把阈值照搬文献的「1/3」是错的——不是因为它不贴近现实，而是因为量纲不可迁移：**
本项目的 `stamina/staminaMax` 与 M&A 模型里的"无氧储备"不是同一个量。
实测 2000 m 全程储备轨迹为 91% → 81% → 72% → 63% → 56% → 48% → 39% → 30% → 21%，
**用 1/3 作阈值时衰减窗口只剩最后约 150 m，效果趋近于零**（实测确实检不出分崩点）。

**更重要的发现**：

> 基线本就**偏快**（批次实测冠军时间中位误差 −2.07 s，即模拟比现实快 2.21%），
> 而加上衰减后完赛时间 124.1 → 127.0 s（**变慢 2.3%**）。

这暗示现实的结构是「**前中段更快 + 末段衰减**」，而模拟是「**全程平推**」——
**两者总时间接近，但形状完全不同**。

⇒ **仅加末段衰减不足以拟合，反而会把总时间推到另一端。**
正确做法必须**同时重构配速的拱形结构**：让前中段更快，由末段衰减收回差额。
这与 `post200Cv`（1.03% vs 现实 4.12%）所指示的"模拟缺少配速形状"完全一致。

## 六、当前状态与未决问题

- 机制已实现在 `sim.js`，参数取扫描中唯一"末段确实减速"的一组（`0.5 / 0.40`）。
- **工程不变量**：已跑 `--scope smoke` 复核（账本、实体交叠、交通可行性）。
- **尚未完成**：完整 156 任务批次对照 —— 这是判定"是否更拟合现实"的唯一依据。
- **已知风险**：末段减速比例 100%（文献 92%），偏多；且整体偏慢。
  需要与配速结构一起标定，而不是单独调这两个数。
