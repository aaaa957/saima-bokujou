# 骑手控制与承诺序列审计

审计读取冻结的生产文本，在私有模块中只暴露三个内部诊断入口。生产文件不由本测试编辑。最新一次通过 10 项检查，正式来源以 JSON 的 sourceHash、testHash 和压缩源快照为准；最终校准冻结后仍应由主代理重跑。

已确认的修复是：报名预测直接采用已经包含 startDelay 的共享 finishPlan.seconds；远处对手按可见速度前推，避免把领头马当作站住；短时推进后增加共同的预算配速回落预测，避免把终端动能全当成损失；完整余程可支付时采用完赛时间价值，已经越线的预测不再给未使用储备收费。终点约 0.01–0.04 m 等价的极小收益仍可能被原有 0.15 m 决策迟滞阈值忽略，这是明确的阈值限制，不是储备收费导致拒绝。

本轮另发现并由主代理修复低速负加速度预测：旧式越过零速后继续积负速度，导致预测时长从 0.3 s 增至 1 s 时位置反而退回旧坐标。新式先求零速时刻，仅积分运动期间。回归检查位置随预测时长单调且停止后保留已走距离。此边界误差约分米量级，不能解释原先七秒量级场尾差。

| 检查 | 证据 |
| --- | --- |
| 对手信息边界 | 近处尾流对手及远处对手的 19 项隐藏状态 getter 均设为抛错；直接 runAI 零读取 |
| 远处位置竞争 | 距 65 m、持续移动的前马在公开速度预测中仍位于前方，预测名次保持正确 |
| 序列时间 | 边界前持续第一动作；准确切换第二动作；整体结束才释放承诺并触发观察 |
| 多动作续验 | 从已经移动 1 s 的真实储备和位置开始，只预测剩下 1+2 s 动作；原绝对距离目标和原承诺时刻保持不变 |
| 真正执行 | 人工固定的合法 4 s 双动作承诺按 60 Hz 实际执行，位置、速度、储备与同 dt 预测相同；能量账差约 1.4e-13，未支付功为 0 |
| 分段尾流 | 同一个可见领马观察拆成两个动作，观察 epoch 只有一个，轨迹和能耗没有额外信用 |
| 终点价值 | 确实越线的候选分数精确等于完赛秒差乘基准配速，不受储备余额差影响 |
| 有限跟跑 | 已有尾流的稳态基准不需要额外“收力再追回”；15 个小对照中无净节能的方案均被拒绝 |

序列物理执行测试采用明确承诺以隔离控制执行；续验测试独立检查真实状态重算。它们没有证明所有交通变化下承诺都能兑现。对手未来动作仍是不确定预测，实际同时交通求解负责最终安全。多阶段尾流必须依赖有限可见路线及实际遮挡，不能把保持标签当作无限遮挡信用。

在稳态同道、基准已处于尾流的例子里，强行先慢后快通常因速度成本凸性增加耗能。本审计不要求 `follow` 模式数量非零，也不通过提高其人为奖励制造通过。后续若需要更多战术变化，应研究尾流、避堵、可达横移和有时限的位置收益如何共同改变可行集合。
