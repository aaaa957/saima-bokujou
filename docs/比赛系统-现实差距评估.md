## 0. 摘要

**一、已实现且无需改动的部分（物理层）。**

引擎已实现分阶段配速划分、三段式体力（耐力池 → 毅力池 → 失速）、可跑距离模型、位置即代价（风阻与尾流）、节奏博弈、坡度系统、弯道几何、碰撞与挤压。该层的实现完整度高于同类模拟器的一般水平，本次评估未建议改动其结构。

**二、主要落差集中在两层。**

1. **竞赛条件层整体缺失。** 斤量（负重）、枠順（闸位）、马体重、马具、班次加磅五项，在现实中每天都在决定赛果，引擎中均无实现。
2. **「展开」维度只实现了一半。** 有节奏博弈（争抢领放的逃马数量），但没有步速档位判定、没有上がり3ハロン、市场模型中没有步速变量。

其中第 2 项同时构成本作核心玩法（信息差套利）的主要缺口。现实中赔率对「展开」的定价系统性偏低，而本作市场模型无从产生这一错误，玩家因此没有可套利的对象。在全部落差项中，该项目的优先级最高。

**三、三轮修正后的当前状态。**

- 步速系统、上がり3ハロン、市场对步速的系统性低估已落地（§9）。
- 跑法胜率的测量口径已修正，并清除三个实现缺陷（§10）。
- 四处与物理或现实不符的底层机制已重做（§11）。
- 跑法胜率的排序现与 JRA 现实数据一致（逃 > 先 > 差 > 追），中长距离（2000~3000m）的偏差在 ±0.28 以内。

**四、尚未收敛的项。**

短途（1200/1600m）跑法胜率仍偏「前有利」；冠军-亚军着差 8.30 马身（现实 1~2 马身）；2000m 冠军用时 110.7~111.8s（现实 118~120s）。三项的成因与后续方案见 §12。

## 1. 现实赛马的结果影响因素全图

按「遗传 → 状态 → 规则 → 环境 → 博弈」五层展开。影响力分级：★越多越关键。

### 1.1 马匹固有层（遗传，短期不可变）

| 因素 | 现实机制 | 影响力 |
| --- | --- | --- |
| **速度** | 短距离能力的基础，决定最高速度上限 | ★★★ |
| **耐力 / スタミナ** | 决定「能跑多远」，是距离适性的根 | ★★★ |
| **距离适性** | 有「最适区间」，偏离则打折。主要由父系与母系（含母父）共同遗传 | ★★★ |
| **爆发力 / パワー** | 出闸与最后 200m 的加速力 | ★★☆ |
| **胜负根性** | 并排冲刺时的「那口气」，弱者会减速 | ★★☆ |
| **气性（気性）** | 气性差的马会抢口（イレ込む）→ 浪费耐力 + 不按跑法走位 | ★★☆ |
| **体质 / 健康** | 决定能否连战、受伤概率、恢复速度 | ★★☆ |
| **成长曲线** | 早熟 / 普通 / 持续 / 晚成，决定巅峰期与衰退点 | ★★ |
| **场地适性** | 草地 / 泥地（ダート）；泥地适性同样由血统遗传 | ★★★ |
| **体格 / 马体** | 胸深宽 = 肺活量大耐力好；体形修长适合长距离；短途马臀腿肌肉显著 | ★★ |

> 参照：ダービースタリオン（ダビマス）的能力模型将「速度・スタミナ・成長・気性・パワー・勝負根性・体質・ダート適性」列为八项基础属性，且种牡马按「距離・成長・ダート・気性・体質・底力・実績・安定」八项遗传。该清单在业界被公认为完整。

### 1.2 马匹状态层（近期可变）

| 因素 | 现实机制 | 影响力 |
| --- | --- | --- |
| **马体重（馬体重）** | 每场赛前约 70 分钟称重公布。变化 20 磅以内 = 状态接近上场；超过则须与「跑入前三时的标准体重」比对 | ★★★ |
| **疲劳 / 休养间隔** | 出赛间隔、放牧质量决定状态 | ★★☆ |
| **斗志 / 状态** | 亮相圈动态：肌肉结实、双目有神 = 佳；急躁出汗、多次起飞脚 = 不佳 | ★★ |
| **试闸表现** | 入闸与出闸熟练度 | ★★ |
| **增重 / 减重** | 「马体变化」本身就是赛前最重要的公开情报之一 | ★★★ |

### 1.3 竞赛条件层（规则，赛前可知）

| 因素 | 现实机制 | 影响力 |
| --- | --- | --- |
| **负磅 / 斤量** | 三种制度：定量（按年龄 Weight For Age）/ 别定（年龄 + 性别 + 收入 + 胜场）/ 让磅（按实力人为加减）。JRA 实例：3 岁 55kg、4 岁以上 57kg、牝馬 −2kg、南半球产 −1kg；赢 G1 加 2kg、G2 加 1kg | ★★★ |
| **枠順 / 闸位** | 转向赛道短途：内侧闸位占优（到第一个弯的距离最短）。左回场地内档有利 / 右回场地高号码档有利；大场数时效果放大；「跑法 × 闸位」需匹配：放头马配内档、后上马配中档 | ★★★ |
| **骑手** | 骑师实力（胜出率 / 三甲率）、换骑手、是否曾策骑该马入前三、减量（见习骑师）；「该马首次配此骑手」也是情报点 | ★★★ |
| **练马师** | 在该场地 / 该距离的成绩 | ★★ |
| **班次** | 升降班直接影响对手强度与负磅 | ★★ |
| **马具 / 蹄铁** | ブリンカー（遮眼罩）改善集中力；蹄铁与矫正具影响发挥 | ★☆ |

### 1.4 环境与赛道层（场地）

| 因素 | 现实机制 | 影响力 |
| --- | --- | --- |
| **距离** | 最核心的分类变量（短途 / 一哩 / 中距离 / 长距离） | ★★★ |
| **场地状态（馬場状態）** | 良 / 稍重 / 重 / 不良。烂地会「拉长」有效距离：快跑能撑一哩的马，软地上可能撑不住 | ★★★ |
| **回向** | 左回 / 右回，与马匹适性直接冲突时打折 | ★★☆ |
| **直线长度（直線の長さ）** | 东京 525m 对比中山 310m。短直道严重压制差し / 追込，长直道则放大末脚价值 | ★★★ |
| **小回り** | 转弯急、直道短的场地（如 Chester）强烈有利于前速马，后上几乎无解 | ★★☆ |
| **坡度（坂）** | 中山 / 阪神的急坂消耗耐力，考验力量 | ★★ |
| **天气（天候）** | 雨、向风（终直逆风显著增加难度） | ★★ |
| **路面磨损 / 内有利↔外有利的翻转** | 同一场地随开催进行，内栏被反复踩踏而变差，「内有利」会在当天中途翻转为「外差し有利」。这是当天最重要的临场情报之一 | ★★★ |

### 1.5 动态博弈层（展开 —— 现实中最被低估的一层）

| 因素 | 现实机制 | 影响力 |
| --- | --- | --- |
| **步速档位（ペース）** | 3F / 4F 分段判定 ハイペース / 平均 / スローペース。「看懂了步速，一半的功课就做完了」 | ★★★ |
| **展开 / 跑法构成（展開）** | 三种形态：Lone Speed 单骑领放 → 前速马偷走比赛、赔率长期被低估；Contested Pace 多马争抢 → 互相消耗、后上型捡漏；No Speed 全场无前速 → 被迫领放者反而易赢 | ★★★ |
| **上がり3ハロン** | 日本赛马的头号指标。步速与上がり是「天平的两端」：慢步速 → 变成末脚对决；快步速却上がり低 = 状态或能力有问题的信号 | ★★★ |
| **市场对展开的系统性错误定价** | 业界共识：betting market almost never prices pace correctly —— 赔率反映实力，但很少反映展开 | ★★★ |
| **被包夹 / 包まれ** | 被封在内栏无路可走，被迫等待或强行突破 | ★★☆ |
| **道次选择与抢位的代价** | 领放者承受全部风阻，跟跑者借尾流省力（约 1~2 马身） | ★★☆ |
| **场地几何** | 弯道半径、起跑点到第一个弯的距离共同决定闸位价值 | ★★ |

### 2.2 已实现但不足的部分

| # | 机制 | 现状 |
| --- | --- | --- |
| A | **闸位 / 内栏优势** | `TRACK_WIDTH` 已从 20 收窄到 11，注释写明「收窄后可以恢复真实的几何差异」，但 `step` 内注释仍写「各道等效等长」，注释与实现自相矛盾。实际 `laneRatio` 被 clamp 在 0.90~1.10，且起跑时 `t` 只在 1.0~5.0 之间，即整个马群挤在 11m 赛道的内侧一半，外侧从未被使用，真正的闸位展开不可能出现（已在 §11.2 修正符号；第四轮把赛道宽度改回 20 米并与渲染对齐、靶位分布到全宽，见 §12.2 第 4~6 项） |
| B | **智力** | 只参与每周训练效率，不进入比赛。该设计本身合理，但需在策划案中明确说明 |
| C | **年龄 / 性别** | 生成后完全不参与比赛计算（无斤量差、无成熟度差） |
| D | **血统力** | 单一标量，只影响市场评分与繁殖，不影响距离适性 / 泥地适性 |
| E | **距离适性** | 由「耐力 = 可跑距离」承担。逻辑自洽，但只回答「能不能跑完」，没有回答「在哪个区间表现最好」（现实存在 optimal sweet spot） |
| F | **骑手** | 只有 4 档速度加成，没有减量、没有换骑手、没有「骑手 × 马」配合 |
| G | **斗志** | 只做 ±5% 属性修正，不产生行为异常（现实中气性差的马会抢口、会不按跑法走） |

### 2.3 完全缺失的部分

| # | 缺失项 | 备注 |

| 10 | **步速档位（ハイ / 平均 / スロー）** | 已由 §9 补上 |
| 11 | **上がり3ハロン** | 已由 §9 补上 |

| 14 | **小回り适性** | 弯道半径随距离放大，但没有「小回り」这个独立适性 |
| 15 | **天气 / 风向** | 只有场地状态，无雨无风 |
| 16 | **路面磨损与内外有利翻转** | 完全没有（现实中最有价值的临场情报之一） |
| 17 | **赛前信息公开面板** | 没有枠順表、没有马体重、没有前走上がり，而这些恰是情报系统最该有误差的地方 |

## 4. 三项关键落差详述

### 4.1 步速与上がり3ハロン缺位 —— 核心玩法的最大缺口 🔴

本作的核心玩法是「信息差博弈」：玩家用有误差的情报，在市场里寻找被错价的价值。

现实世界中最大的市场错价来源就是「展开」。业界共识为：赔率充分反映了马匹实力，但几乎从不正确反映步速与展开。

而基线版本的市场模型（`MARKET`）只有六个公开信号：战绩、骑手、血统、年龄、适性、体格，其中没有任何一个与步速 / 展开相关。由此产生两个后果：

- 现实中「看懂步速就能赚钱」这条最重要的技术，在本作里没有对应的对象可看；
- 市场也没有犯「看错步速」这个错误，玩家因此无从利用。

**结论：补上「步速档位 + 上がり3ハロン」不属于数值拟真的锦上添花，而是直接扩大核心玩法的维度。该项在全部落差中的优先级最高。**（已于 §9 实施）

### 4.2 竞赛条件层整体缺失（斤量 / 枠順 / 马体重） 🔴

现实中这些因素每天都在决定赛果，且全部是「赛前公开、但有解读空间」的信息，正好是情报系统最理想的载体。

| 项 | 现实规则 | 落地到本作后的作用 |
| --- | --- | --- |
| **斤量** | 3 岁 55 / 古馬 57 / 牝馬 −2 / G1 胜者 +2 | 一个直接的速度惩罚，且使「牝馬」「年龄」终于有意义 |
| **枠順** | 内档有利（急弯短途尤甚），跑法 × 档位需匹配 | 把 `t` 扩展到全幅 11m，显式闸位号，恢复真实的 lane 几何 |
| **马体重** | 赛前 70 分钟公布，±20 磅判据 | 逐场随机波动 + 公开但可被误读的情报 |
| **班次加磅** | 赢 G1 加 2kg | 让「连胜溢价」有真实依据 |

补齐该层可同时解决三个问题：数值更真实；`年龄` / `性别` 从死数据变为活变量；情报系统新增四个可误差对象。

### 4.3 距离适性只有「能不能跑完」，没有「甜区」 🟠

现有模型为「耐力 70 → 2240m」，跑得完就跑，跑不完就崩。这正确回答了「这匹马跑不跑得完 2400m」，但没有回答「这匹马在 1600m 还是 2400m 更可能赢」。

现实中后者由血统决定（父系平均胜出距离、母父的影响），且存在一个最适区间：

- 偏短：爆发型，1600m 有威胁，2400m 会「撞墙」
- 偏长：伸展型，1600m 显得迟钝，2400m 才如鱼得水

**改进方向：将「血统力」这一单一标量拆分为「适性距离中心」与「适性宽度」两个遗传量，并令「偏离甜区」产生乘性惩罚。** 该拆分带来的效果：

- 距离适性由血统遗传，符合现实，也使繁殖系统具备实质意义；
- 繁殖不再只产出「数值更高」的马，而是产出「适性不同」的马，玩法深度显著提升。

## 6. 改进路线

### 6.1 阶段一 · 补齐「展开」层（最高优先）

1. **步速档位**：由争抢强度 + 各马跑法，推导本场步速（スロー / 平均 / ハイ），并影响全场配速曲线。
2. **上がり3ハロン**：终盘 600m 分段计时，作为赛后公开情报输出。
3. **市场误判**：给市场加一个「看得见但会误判」的步速信号，制造系统性错价。

预期效果：`race-drama` 转绿（比赛有悬念），`market` 相关系数回升，核心玩法出现新维度。

### 6.2 阶段二 · 补齐「竞赛条件」层

4. **斤量**：年龄 / 性别 / 战绩 → 负重 → 速度惩罚。
5. **枠順**：显式闸位 + `t` 扩展到全幅 + 恢复真实 lane 几何。
6. **马体重**：逐场波动 + 公开情报。
7. **班次加磅**。

预期效果：`年龄` / `性别` 复活，情报系统新增四个可误差对象，闸位展开成为可研究的技术。

### 6.3 阶段三 · 重标定与收口

8. `stamina-range`：把 `RANGE_CALIB` 改为按目标耗尽里程解方程。
9. `style-by-distance`：补齐短途几何约束后重新平衡。
10. `attribute-impact`：进一步稀释速度。
11. README 验证报告全部替换为实测数字，并加 CI 自动运行。

### 6.4 优先级判定

若只实施一项，应选择阶段一第 1 项（步速档位）。理由：它同时改善 `race-drama` 与 `market` 两项红灯，并为核心玩法打开新维度，投入产出比最高。

## 8. 阶段一设计（步速系统）

### 8.1 诊断 —— 基线 `paceContest` 效果有限的原因

基线实现：

```js
// 争抢强度
let contesters = 0;
for (const H of act) if (H.style === '逃') contesters++;
race.paceContest = Math.max(0, Math.min(RACE_F.paceContestCap, contesters) - 1);
// 速度端（序盘/中盘）
if (race.paceContest > 0 && (ph.key === 'open' || ph.key === 'mid'))
  runCoef += race.paceContest * RACE_F.paceContestCoef;      // +0.012/匹
// 油耗端（序盘/中盘）
const contestDrain = 1 + race.paceContest * RACE_F.paceContestDrain;   // +14%/匹
```

存在两个结构性问题。

**问题一：速度加成是「全场平摊」的，不分跑法。**

现实中步速由领放者设定，它只把靠前争抢的马拖着走；后上型仍按自己的节奏跑，快步速对它的意义是「差距被拉开」，而不是「被拖着提速」。基线写法对逃、先、差、追一视同仁，等于抹掉了「展开」最关键的那层差异。

**问题二：油耗端被归一化抵消。**

```js
const effort = clamp(H.v / race.avgV, 0.6, 1.6);   // ← 相对全场均速
const effortDrain = Math.pow(effort, RACE_F.effortExp);
```

步速抬高全场速度时，分子（`H.v`）与分母（`race.avgV`）同时变大，`effort` 几乎不变，`effortDrain` 也随之几乎不变，即步速在油耗端的效应被数学抵消。

结果：`paceContest` 只剩一个静态的 `1.14^n` 消耗惩罚，没有真正改变体力分配。这正是 `race-drama` 报出「71% 场次半程领先者即冠军」的根因：比赛中段的节奏博弈看似存在，实则没有传导到末段的实力重排。

### 8.2 设计

**① 采集：争抢强度。**

```js
// 想抢领放的意愿 = 逃（全部）+ 先（部分），用斗心调制「敢不敢抢」
let want = 0;
for (const H of act) {
  if (H.style === '逃') want += 1.00 * (0.6 + 0.4 * (H.morale / 100));
  else if (H.style === '先') want += 0.35 * (0.6 + 0.4 * (H.morale / 100));
}
const fieldFactor = 1 + (act.length - 8) * 0.02;
const paceStrength = (want / 1.15) * fieldFactor;   // 1.0 = 标准节奏
```

**② 判定：步速档位（可播报、可被市场误判）。**

```js
const paceLevel = paceStrength < 0.85 ? 'スロー'
                : paceStrength > 1.15 ? 'ハイ' : '平均';
const paceCoef  = 1 + 0.045 * (paceStrength - 1);   // 对前段速度的拉动幅度
```

**③ 拉动前部速度 —— 按跑法衰减（解决问题一）。**

```js
const PACE_PULL = { '逃': 1.00, '先': 0.60, '差': 0.20, '追': 0.10 };
if (ph.key === 'break' || ph.key === 'open' || ph.key === 'mid')
  runCoef += (paceCoef - 1) * PACE_PULL[H.style];
```

**④ 节奏项 —— 只作用于「承受步速」的马（解决问题二，核心）。**

不再依赖被归一化抵消的 `effortDrain`，而是增加一个不参与归一化的独立项：

```js
const paceTax = 1 + 0.35 * PACE_PULL[H.style] * Math.max(0, paceStrength - 1);
drain *= paceTax;
```

该项的关键性质：作用于绝对量，不与 `avgV` 相除，因此不会被抵消。同时因为乘了 `PACE_PULL`，快步速的代价几乎全部落在逃马与先行马身上，后上型的油耗基本不变，这正是现实中「快节奏烧掉前速马、后上型捡漏」的机制。

**⑤ 上报为公开情报。**

- 本场步速档位（スロー / 平均 / ハイ）
- 赛后揭穿的上がり3ハロン（末段 600m 用时），日本赛马的头号指标
- 二者构成「天平两端」：慢步速 → 上がり快是常态；快步速还能跑出快上がり，才是真本事

**⑥ 产出：市场误判 → 套利空间。**

```js
// 市场看得见步速（公开），但只做打折处理：真效应 ×0.4，剩余 0.6 即玩家的错价空间
marketPaceAdjust = 1 + 0.4 * (truePaceEffect - 1);
```

由此形成核心玩法所需的缺口：

- 单骑领放：全场不抢 → 领放者省油 → 容易「偷走比赛」，但市场只轻微上调它；
- 多马争抢：前速马集体烧油 → 后上型受益，但市场只轻微下调前速马。

### 8.3 三种展开形态的涌现条件

| | スロー（单骑领放） | ハイ（多马争抢） | 无前速 |
| --- | --- | --- | --- |
| `paceStrength` | < 1 → 税额 0 | > 1 → 重税 | 低 |
| 领放者 | 省油、控制节奏 | 烧油、末段崩溃 | 被迫领放但节奏慢 |
| 跟跑者 | 借尾流但节奏慢 | 借尾流、相对受益 | 措手不及 |
| 后上型 | 追不上（对手有余力） | 捡漏，高赔率 | 无步速可借，反而吃亏 |
| 典型胜者 | 前速马 | 差し / 追込 | 被迫领放者 |

三种形态全部由公式自动产生，无需为它们分别写分支。

### 8.4 代码落点

| 位置 | 改动 |
| --- | --- |

| `step()` 第 1 步 | `paceContest` 计数升级为 `paceStrength`（含斗心与场数）；速度端改按跑法衰减 |

### 8.5 风险与取舍

- **风险一：过度修正。** `paceTaxK` 若过大，会变成「逃马必输」。应对方式为：以四跑法胜率均衡为收敛目标，用 `style-by-distance` 跨距离校验。
- **风险二：与既有 `draftSave` / `leadCost` 叠加。** 两者都在惩罚领放，需先测出当前领放惩罚的实际量级，再决定 `paceTaxK` 的起点，避免双重惩罚。（该风险在 §11 中确认成立，并已通过修正风阻项解决。）
- **取舍：不修改 `effortExp` 归一化本身。** 它的存在是为了避免「掉速 → 跑更久 → 耗更多 → 掉更快」的死亡螺旋（代码注释有记录），因此正确做法是旁路新增一个绝对项，而不是修改它。

### 8.6 验收标准

1. `race-drama` 半程领先者即冠军的比例 ≤ 60%（基线 71%）
2. `style-by-distance` 各距离极差 ≤ 25%（基线 1200m 达 75%）
3. `market` 相关系数 ≥ 0.25（基线 0.102），且出现「上帝视角 ROI 下降、市场逆势 ROI 保持 > 1」
4. 新增 `tests/pace.js` 三项断言全绿

### 9.1 过程中查出并修复的实现缺陷

以下均属实现错误，而非参数取值问题。按影响排序：

| # | 缺陷 | 后果 |
| --- | --- | --- |
| 1 | `STYLE_COEF` 积分方向反了（差 1.05757 > 追 1.05599 > 先 1.05687 > 逃 1.05185） | 1200m 出现「追 74% / 逃 0%」的完全反向结果 |
| 2 | 回向适性系数被无条件乘进全程（含直道） | 生成器给约 11% 的马分配不符回向，造成全程 10% 降速 |
| 3 | 内外道几何符号写反（`(R+t)/R`），且注释写着「各道等效等长」，自相矛盾 | 外道白拿最多 3.6% 速度，而后上型恰好跑外道 |
| 4 | 失速无限崩溃：`H.v · 0.95^dt` 一路衰减到 `STALL_SPEED = 2 m/s` | 末位被拉到 153 马身（约 367m） |
| 5 | 爆发力项在毅力阶段直接归零 | 体力耗尽的瞬间产生速度断崖，是马身差距失控的主因之一 |
| 6 | 加速项构成正反馈：`accel ∝ (1 − stRatio)`（已消耗比例） | 「跑得越快 → 耗得越多 → 末段加速越大」，与注释声称的「省下的油变现」相反；实测让逃马在 1200m 拿到 80% 胜率（而系数优势仅 0.31%） |
| 7 | 疲劳惩罚过重（85~100 → 0.6，>100 → 0.3） | 单项即可贡献 8~40% 速度差 |
| 8 | 碰撞减速下限 0.5 | 被撞一下掉一半速度 |
| 9 | 跑法模板把耐力与速度也按跑法分化（追 耐力仅 40~65 ≈ 1664m） | 后上型在马厩里就跑不完 2000m，马群裂成「两匹能跑完 + 六匹崩盘」 |
| 10 | `baseSpeed` 斜率 0.045 | 同场 level 跨度 8~10 点 → 基速差 4.1%，而现实同班次只有 2~3% |

### 9.2 新增功能

- **步速系统**：`paceStrengthOf()` 只吃公开信息（跑法 + 斗心），在 `createRace` 判定一次并冻结（每帧重算会被赛末减员稀释，实测 2 匹逃马的场次会被算成 0.67）。
- **`pacePull` + `paceSpeedK`**：按跑法衰减地拉动前段速度（逃 1.0 / 先 0.6 / 差 0.2 / 追 0.1）。
- **`paceTax`**：不参与归一化的绝对项。旧的 `contestDrain` 乘在 `effortDrain` 上，而 `effort = v / avgV` 会在步速抬高全场速度时分子分母同时变大，效应被数学抵消。
- **上がり3ハロン**：记录冲过终点前 600m 的时刻，完赛时相减；`snapshot` 已暴露 `final3f`。
- **市场误判 pace**：`marketPaceDamp = 0.40`，市场看得见节奏，但只兑现真效应的 40%。

## 10. 第二轮：跑法胜率的测量口径与缺陷修正（2026-10-01）

### 10.1 测量口径修正

原 `tests/realism.js` 的 ① 段用「4 跑法各 2 匹」构成 8 匹马，等于让逃马占到 25%。而游戏自身的 `makeField` / 生涯对手生成只产出 1~2 匹逃（现实中逃马也只占约 8~14%）。固定 2 匹逃会让每一场都判成ハイペース，逃马被 `paceTax` 永久重罚，因此此前测出的「追 74% / 逃 0%」有相当部分属于测量方法造成的假象。

口径同时修正为：以胜场除以该跑法的出赛次数（基准 = 1/8 = 12.5%），而非「胜场 / 场次」，因为各跑法的出赛次数并不相等；且属性必须全同源（连斗志 / 疲劳 / 骑手都统一），否则测到的是能力而不是跑法。

②③ 段的 level 分配也改为独立于跑法随机。旧版 `level = 64 + (i%3)*2` 与 `STYLES[i%4]` 耦合，会让某匹「差」恰好拿高 level，测出的胜率是能力优势而非跑法优势。

### 10.2 现实基准

数据源：bakenshi.net 汇总的 JRA「全競馬場同距離区分」脚質別 1着率。口径为「胜场 / 该跑法出赛次数」，脚質按 4 角通過順位机械分类。

| 区间 | 逃 | 先 | 差 | 追 | 相对基准 |
| --- | --- | --- | --- | --- | --- |
| マイル 1400-1800（n = 54,888） | 17.4% | 10.5% | 7.3% | 3.0% | **2.19 / 1.32 / 0.92 / 0.38** |
| 中距離 1900-2100（n = 22,840） | 17.5% | 10.7% | 8.2% | 3.5% | **2.05 / 1.25 / 0.96 / 0.41** |

**两项与直觉相反的事实：**

1. **现实中「逃」的 per-start 胜率在各距离都是最高**（≈2.1~2.2× 均等），「追」最低（≈0.4×）。即顺序为 逃 > 先 > 差 > 追。
2. **在 1400~2100m 之间，脚质优势几乎不随距离变化**（逃 17.4% 对比 17.5%）。距离依赖只出现在最高级别：東京芝 G1 近 37 战，逃 0 胜（上級条件ほど逃げ切りが難しい）。

> 成因说明：JRA 的脚質按 4 角通過順位划分，「逃」= 4 角领跑者，每场仅 1 匹，而这匹马本身就是「走位成功」的结果，存在幸存者偏差。JRA-VAN 亦明确说明该分类可能与一般所称的「脚質」不一致。故上表不宜当作纯粹的策略优劣比较，但「前后位优势的方向」是可靠的。

由此，本作原有的设计前提「短途靠前速、长途靠后上」，在 JRA 全体赛事的聚合数据里并不成立；它只在最高级别（G1）成立。

### 10.3 本轮修正的实现缺陷

| # | 缺陷 | 后果 | 修法 |
| --- | --- | --- | --- |
| 1 | **终盘动作表不对称**：`追` 几乎永远「打鞭」(+0.05)，`逃` 只要在耐力阶段也持续「打鞭」，而 `先` / `差` 是「打鞭 / 推骑交替」只有 +0.035 | 终盘占耦合后有效权重 0.300（最大），等于白送「追」约 1.5% 终盘速度 ≈ 0.4 秒 | 抽出 `finalDrive()`，四个跑法共用同一条规则 |
| 2 | **节奏项只罚不奖**：`paceExcess = Math.max(0, paceStrength - 1)` | 「单骑领放」相对「多马争抢」只是少交罚金，领放本身仍是净亏损，导致「マイペースで逃げ切る」无法发生 | 改为对称（允许 < 1 省油），加上下限 `paceAdjFloor` / `paceAdjCeil` |
| 3 | **场次生成器最多只产出 2 匹逃**（写死 `['逃','先','差','追','先','差','追',随机]`） | `paceStrength` 上不去，ハイペース 成为死代码（实测 3000 场仅 0.7%），「多马争抢 → 前速崩溃 → 后上捡漏」整条路径不可达 | 新增 `fieldStyles()`：按 JRA 脚质构成抽取（逃 16 / 先 28 / 差 30 / 追 26），保底 1 匹逃 |

缺陷 1 的受控证据（属性完全同源 · 4 差 + 4 追 · 2000m · 每档 300 场）：

| 实验 | 差 | 追 |
| --- | --- | --- |
| 修前 | 19.0% | **81.0%** |
| 交换两者系数 | 3.0% | 97.0% |
| 系数完全拉平 | 8.0% | **92.0%** |

即：系数几乎不是原因。把两者系数完全拉平后「追」仍拿 92%，主因是动作表。修后同一实验为差 53.0% / 追 47.0%，与现实「差 > 追」的方向一致。

| 跑法 | 现实 | 第二轮实测 | 判读 |

### 10.5 本轮遗留问题

1. **「逃」的目标档位未定。** 完全贴合 JRA 聚合数据的方案是让「逃」在 1400~2100m 全区间都最强（≈2.2×），这意味着整体倾向「前有利」并放弃「长途后上主导」的原设计意图；折中方案是短途逃领先、中距离先 / 逃接近、长途逃最弱但不被碾压，并把「逃在最高级别崩盘」做成班次相关机制（对应现实的 G1 现象，可复用现有的 `RACE_TIERS`）。该问题在 §11 中按「贴合现实」原则解决。
2. **冠军用时出现新偏移。** 本轮改动后 2000m 冠军 110.9~111.9s，比现实 118~120s 偏快约 6%（节奏项对称化让前段马省下体力），应与马身差距一并做联合标定，两者共用 `baseSpeed` 这一把标尺。

## 11. 第三轮：底层机制重做与系数重标定（2026-10-01）

本轮遵循的原则：以模拟现实为优先，不以改动规模为取舍依据；当底层机制与现实存在差距时，直接修正机制而非在机制外围调整参数。

### 11.1 杠杆定位

对「逃」的 per-start 胜率倍数做单杠杆扫描（属性同源 · 真实构成 · 每档 150 场）：

| 场景 | 1200m | 2000m | 3000m |
| --- | --- | --- | --- |
| A 现状 | 1.02 | 0.44 | 0.31 |
| B 去掉风阻差（lead 1.00 / draft 1.00） | **1.80** | **0.95** | **1.12** |
| C 加大节奏掌控收益 | 0.85 | 0.27 | 0.14 |
| D 两者同时 | 1.66 | 0.68 | 0.85 |

结论：风阻项（`leadCost` / `draftSave`）是头号机制，且其实现方式与物理不符（见 §11.2）；节奏收益是第二杠杆；跑法系数只是第三。此前多轮调整集中在系数上，杠杆选择本身有误。

### 11.2 本轮修正的四处底层机制偏离

| # | 偏离 | 与物理 / 现实不符之处 | 修法 |
| --- | --- | --- | --- |
| 1 | **风阻项重复计费**：`leadCost 1.05` 给领放者加价，同时又用 `draftSave 0.93` 给跟跑者打折，凭空造出 13% 的落差 | 物理上「领放者的风阻」就是基准，省下的只是跟跑者的 5~10%，不存在额外的加价项 | `leadCost 1.00`（基准）、`draftSave 0.90`（省 10%） |
| 2 | **马群耦合压缩对象错误**：压缩的是乘完 `runCoef` 之后的 `pot`，把战术差也一并抹平 | 逃的领先完全来自序盘 / 中盘系数，被压掉后就永远建立不起领先，整场比赛被压成一场 600m 短跑，后上型系统性占优。现实中马群锁住的是能力差（强马不能一骑绝尘），不是战术 | 改为只压缩 `H.base`（纯能力速度），跑法系数完整保留。属性同源时耦合自动退化为无操作，跑法效应因此可被干净读出 |
| 3 | **内栏几何优势被关闭**：`laneBias` 曾被压到 0.15 | 弯道上跑外道要多跑 `(R+t)/R` 的距离，这是「内栏省距离」这条最基础的现实机制，也是前位价值的来源 | `laneBias` 0.15 → 0.55（外道可略微跑快补偿，故非纯几何的 100%）。第四轮赛道宽度改回 20 米后几何差异变大，该值下调至 0.05 以维持整体量级，见 §12.2 |
| 4 | **被堵不再有代价**：`collisionCoef` 下限曾被抬到 0.90 | 现实中「前が詰まる」是致命的：必须收力、绕行、错过加速时机。且领放者永远不会被堵，这正是前位最硬的优势 | 下限 0.90 → 0.75（被撞方 0.85） |

### 11.3 场次构成补全

`fieldStyles()` 取代写死的 `['逃','先','差','追','先','差','追',随机]`：按 JRA 芝脚质构成（逃 16 / 先 28 / 差 30 / 追 26）抽取，保底 1 匹逃。配合 `paceRef 1.72`、`paceWeight[先] 0.28`、新增的 `paceCreditK`（慢节奏一侧的收益系数），步速三档全部可达：スロー 74.9% / 平均 18.9% / ハイ 6.2%（此前 ハイ 恒为 0.7%，属死代码）。

### 11.4 结果：跑法排序已与现实一致

重标定 `STYLE_COEF` 后的实测（属性同源 · 真实构成 · 每档 250 场）：

| 1200m | 3.19 | 0.68 | 0.52 | 0.23 | 2.60 / 1.25 / 0.85 / 0.32 | ±0.59 |

| **2000m** | 1.77 | 1.03 | 0.95 | 0.42 | 2.05 / 1.25 / 0.96 / 0.41 | ±0.28 |

### 11.5 标定方法记录

## 12. 第四轮：动作、车道与体力变现的机制细节（2026-10-01）

### 12.1 诊断：先定位真正的杠杆

在调整任何参数之前，先做三项受控测量。

**（1）动作习惯的权重。** 统计各跑法全程实际使用的动作构成，折算成对速度系数 `runCoef`
的平均贡献（`ACTION_DEF[a].coef`）：

| 跑法 | 推骑 | 打鞭 | 收力 | 斜行 | 不催 | 平均 coef 贡献 |
| --- | --- | --- | --- | --- | --- | --- |
| 逃 | 54% | 9% | 24% | 2% | 11% | **+0.352%** |
| 先 | 41% | 10% | 31% | 1% | 18% | +0.180% |
| 差 | 42% | 10% | 35% | 1% | 12% | +0.161% |
| 追 | 23% | 9% | 39% | 1% | 26% | **−0.036%** |

对照：`STYLE_COEF` 的幅度只有 ±1%。即**骑手的催马习惯比跑法本身更能决定胜负**。

**（2）动作系数的净影响。** 把 `ACTION_DEF` 的 coef 全部归零（其余不变）后，「追」的
per-start 胜率直接掉到 0.00，说明它当时完全靠末段「打鞭 +5%」撑着，其体力 / 节奏 /
跑法机制本身不足以获胜。

**（3）烧光体力的代价。** 8 匹全同跑法、属性同源的对照（2000m，每档 200 场）：

| 跑法 | 冠军用时 | 相对最快 | 结束耐力 |
| --- | --- | --- | --- |
| 逃 | 115.58s | 0.000% | **0.8%**（力竭） |
| 先 | 116.56s | +0.851% | 44.2% |
| 差 | 116.66s | +0.935% | 41.3% |
| 追 | 117.36s | **+1.546%** | 44.3% |

「逃」把耐力烧到只剩 0.8% 却最快，「追」还剩 44% 体力却最慢 —— 即
**省下的体力在末段换不到任何东西，而把油烧光没有代价**。这才是「追」在混合场次里
胜率归零的根因，而不只是系数问题。

### 12.2 本轮修正的机制偏离

| # | 偏离 | 处理 |
| --- | --- | --- |
| 1 | **催马被实现成无条件速度加成**（推骑 +2% / 打鞭 +5% / 收力 −3%），幅度是系数表的 2~5 倍 | 收窄至 +0.8% / +1.8% / −1.0%，收益与代价交还体力侧 |

## 13. 遗留问题与后续工作

### 13.1 跑法胜率

**问题：短途（1200m）仍偏「前有利」，且是跨越三轮的遗留项。**

- 第四轮实测：1200m 逃 2.99（目标 2.60）、追 0.06（目标 0.32）；1600~3000m 已全部进入 ±0.41。
- 成因：短途体力几乎不耗尽，胜负由位置与系数决定；而长途由体力耗尽把差距抹平。
  第四轮已补上「余力变现」机制（§12.2 第 3 项），中长途因此达标，短途的剩余偏差
  来自弯道占比（1200m 占 52.4%）与体力不耗尽两处。
- 候选方案：为「先行」补充一条现实机制 —— 现实中先行马占住 2~4 位的包厢（好位），
  既省路程又最早取得进路；引擎目前只给了它中等的横向位置，缺少「最早取得进路」这一维度。

### 13.2 马身差距

- 第四轮实测：冠军-亚军着差中位数 5.36 马身（现实 1~2）、冠军-末位 69.08（现实 10~25）。
  已较本轮起点（8.30 / 62.50）收窄，但仍差一个量级。
- 已确认无效的手段：压平 `baseSpeed` 斜率。实测将斜率压缩 4 倍仅让 1-2 名着差从 12.20
  降到 9.54 马身，却把「速度 +20」的胜率从 72% 打到 18%（低于基准 25%），即属性失去意义。
- 待确定的取舍：**场次内能力跨度**（`FIELD_LEVEL_SPAN`）。第三轮把它从 ±10 收到 ±2，
  是当时最大的一笔收益；继续收窄与「属性仍有区分度」直接冲突，需先确定两者的优先次序。
- 与冠军用时（§13.3）共用 `baseSpeed` 一把标尺，应联合标定。

### 13.3 冠军用时

- 第四轮实测：2000m 冠军 110.4~113.3s，现实 118~120s，偏快约 5%；本轮起点为 110.7s，基本持平。
- 成因：节奏项对称化与「余力变现」机制都会让末段更快。
- 处理方式：与 §13.2 的马身差距共用 `baseSpeed` 这一把标尺，应联合标定，不宜单独调整。

### 13.4 尚未实施的落差项

§2.3 中除已补的三项（步速档位、上がり3ハロン、市场误判 pace）之外，其余 14 项均未实施。
其中优先级较高的为：

1. **竞赛条件层**（斤量 / 枠順 / 马体重 / 班次加磅）—— 可使 `年龄` / `性别` 从死数据变为
   活变量，并为情报系统增加四个可误差对象。第四轮把赛道宽度与靶位分布理顺之后，
   「枠順 → 起步横向位置」这条链路已具备落地条件。
2. **距离适性甜区与血统遗传**（§4.3）；
3. **路面磨损与内外有利翻转** —— 现实中最有价值的临场情报之一。

## 附录 A · 标定口径与外推说明（历史口径）

### A.1 跑法胜率的口径

- **基准**：无跑法优势时，每个跑法的 per-start 胜率 = 1 / 出场头数 = 1 / 8 = 12.5%。报告中的「相对基准」即实测 per-start 胜率除以 12.5%。
- **属性同源**：测量跑法效应时，所有马匹的属性、斗志、疲劳、骑手等级全部统一，仅跑法不同。若保留属性差异，测到的是能力优势而非跑法优势。
- **出赛构成**：与 `sim.js` 的 `fieldStyles()` 同源（JRA 芝脚质构成，保底 1 匹逃）。不得使用「4 跑法各 2 匹」，因为那会让逃马占 25%，导致每一场都判成ハイペース。

## 15. 连续出力与骑乘决策（2026-10-01，v2026.10.01.6）

本轮核心实现与功能回归通过；正式工程数值检查 **14项中13项通过**。
唯一未达项是首次独立留出组生成阵容的冠军—亚军着差p90 **10.3186马身**，超过原定10马身；
脚本返回退出码1，机器报告保留 `passed: false`，没有放宽门槛或在读到留出结果后继续调本版参数。
因此本版是可玩的核心更新，尚未完全完成严格数值标定或现实拟合。

本版将比赛改为“骑手选择目标配速 → 马匹在功率与加速约束下响应 → 实际运动决定消耗 → 剩余能力影响后续配速”的闭环。
§1–14 与附录 A 保留历史版本的实验与调参过程，其中旧的阶段公式、固定耗尽里程、跑法外推胜率和验证数字均不代表本版。
当前预设策略不会按四角实际位置统计表拟合，也不要求四种跑法冠军占比各为25%。

### 15.1 实现范围与机制变化

| 原问题 | 本版行为 |
| --- | --- |
| 首帧由静止直接赋到比赛速度，动作和阶段直接改变速度 | 每匹马具有真实速度、出闸延迟和有限加减速；目标配速经过响应过程形成实际速度，加速还受剩余功率限制 |
| 消耗以自身速度除以全场均速，远处慢马会直接改变本马耗能 | 成本取决于自身速度、加速、场地、坡度、弯道和实际尾流；移除全场均速作为体力消耗基准与全局能力压缩 |
| 耐力用完才启用毅力的串行油箱 | 持续供能、短时储备与疲劳余量共同影响能力；两项储备并行耗用，收力减少消耗，不凭空回满储备 |
| 储备用尽仍能透支不存在的能量完成加速 | 稳态可达速度与能耗读取同一成本函数；额外加速只能使用扣除当前运动需求后的功率余量，储备扣款不超过实际余额 |
| 步速由赛前跑法数量冻结，按跑法发放节奏税或收益 | 赛前步速仅为预测；比赛步速来自实际分段，近距离领放争抢通过骑手选择配速形成消耗 |
| 固定完成70%路程后获得终盘速度奖励 | 骑手估算剩余路线、弯道、坡度、外道弧长和加速所需储备，决定发动；跑法与骑手等级影响位置偏好和判断，不直接发阶段速度奖励 |
| 争抢位置可过早耗光储备 | 早段抢位受剩余行程预算约束，留出后续配速所需余量 |
| 后上马固定走外道，外道成本被人为削弱 | 所有跑法均可跟跑和择短路；弧长换算使用赛道参考线与实际道次，保留真实路线差异 |
| 赛道半径随比赛距离放大 | 三种独立体育场布局通过起跑偏移和多圈支持不同距离；物理、主镜头、小地图读取同一赛道几何 |
| 起跑横向位置无序、可重叠；强行突破绕过实体阻挡 | 本轮八匹阵容有唯一、有序且按种子分配的闸位；横移有身体间距和速度约束，真实前马限制推进，不再豁免穿过堵马 |
| 失效超车承诺使马长时间锁在外道 | 超车目标远离、已完成或当前路线已没有推进优势时释放承诺，重新选择短路；可完成的横移意图仍保持 |
| 无法解释单场为何跑崩或冲刺过早 | 比赛与逐马记录每200米通过时间及余力，另记录发动点、累计跟跑与受阻时间、实际功与储备支出、最高速度 |

页面赛后诊断默认折叠，普通结果表保留名次、时间、着差和赔率。分段通过时间按实际位置插值；
比赛分段取各标志点首匹马的时间，不一定由同一匹马领跑，非200米整倍数距离另记录终点末段。
MC 的 `doc` / `balanced` 是兼容旧脚本的别名，均进入本版模型，页面改为同种子配对复跑；不把相同模型的结果解释为旧版改进。
已有生涯的未完成场次使用本版引擎，已结算战绩与马券不回算，已有注单保留下单赔率。

模型结构参考了将速度、推进力与能量共同建模的研究思路：[Mercier 与 Aftalion，Optimal speed in Thoroughbred horse racing，PLOS ONE，2020](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0235024)。
该论文用真实比赛追踪数据辨识参数；本项目没有复现其拟合方程或数据结果。这里的速度立方成本、相对功率、供能与储备参数仍是游戏近似。

### 15.3 当前模型的边界

三种布局与周期坡度仍为抽象对照场地，生涯中的马场名称映射到抽象布局，尚未按真实马场的尺寸、高程与特定起跑点逐一拟合。
归一化功率与储备不是直接测量的生理单位；尾流收益、弯道负担、疲劳曲线、骑手观察间隔和预设位置偏好也仍需真实分段数据约束。
八匹、70级、良地草地的主矩阵不能证明所有级别、斤量、头数、草地磨损、风况与生涯阵容都已贴近现实；斤量与路面内外差异仍未实装。

实际生成阵容的长途首尾跨度仍需单独观察。冠军—亚军门槛通过只能说明头部着差达到当前工程量级，不能据此认定尾部差距、所有跑法或距离适性已经完成现实标定。
后续应优先采集同班次、同赛道的实际分段与着差数据，检查尾部落后的成因和骑手配速；不能用额外跑法速度系数掩盖路线或体力问题。

本版页面验证使用真实页面代码运行环境与 canvas 绘制记录。此次没有成功取得新版本真实浏览器截图，不把历史 §14 的人工截图检查记为本版验收。
