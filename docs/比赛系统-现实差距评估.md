# 赛马风云 · 比赛系统与现实赛马的差距评估

> 评估对象：`sim.js`（比赛引擎，2114 行）对照真实赛马（以 JRA 日本中央竞马 + 香港赛马会规则为主）
> 生成日期：2026-10-01
> 用途：作为后续「让比赛系统尽可能贴近现实」的改进依据

---

## 0. 一句话结论

**引擎的「物理层」已经相当扎实**（分阶段配速、三段式体力、可跑距离、位置即代价、节奏博弈、坡度、碰撞挤压），
这些在同类模拟器里属于超前实现。

**真正的落差集中在两层：**

1. **竞赛条件层几乎完全缺失** —— 斤量（负重）、枠順（闸位）、马体重、马具、班次加磅，现实中这五项每天都在决定赛果，游戏里一个都没有。
2. **「展开」只做了一半** —— 有节奏博弈（逃马数量），但**没有步速档位、没有上がり3ハロン、没有市场对步速的系统性误判**。
   而「市场对 pace 定价错误」恰恰是**本项目核心玩法（信息差套利）最大的机会缺口**。

此外，当前 5 项验证里 3 项为红，其中至少 2 项可直接用本报告的落差解释（详见 §5）。

## 1. 现实赛马的结果影响因素全图

按「遗传 → 状态 → 规则 → 环境 → 博弈」五层展开。括号内为现实中的影响力级别（★越多越关键）。

### 1.1 马匹固有层（遗传，短期不可变）

| 因素 | 现实机制 | 影响力 |
|---|---|---|
| **速度** | 短距离能力的基础，决定最高速度上限 | ★★★ |
| **耐力 / スタミナ** | 决定「能跑多远」，是距离适性的根 | ★★★ |
| **距离适性** | 有「最适区间」，偏离则打折。**主要由父系与母系（含母父）共同遗传** | ★★★ |
| **爆发力 / パワー** | 出闸与最后 200m 的加速力 | ★★☆ |
| **胜负根性** | 并排冲刺时的「那口气」，弱者会减速 | ★★☆ |
| **气性（気性）** | 气性差的马会抢口（イレ込む）→ **浪费耐力 + 不按跑法走位** | ★★☆ |
| **体质 / 健康** | 决定能否连战、受伤概率、恢复速度 | ★★☆ |
| **成长曲线** | 早熟 / 普通 / 持续 / 晚成，决定巅峰期与衰退点 | ★★ |
| **场地适性** | 草地 / 泥地（ダート）；泥地适性同样由血统遗传 | ★★★ |
| **体格 / 马体** | 胸深宽=肺活量大耐力好；体形修长适合长距离；短途马臀腿肌肉显著 | ★★ |

> 参考：ダービースタリオン（ダビマス）的能力模型把「速度・スタミナ・成長・気性・パワー・勝負根性・体質・ダート適性」列为八项基础属性，
> 且种牡马按「距离・成长・ダート・気性・体質・底力・実績・安定」八项遗传 —— 这是业界公认的完整清单。

### 1.2 马匹状态层（近期可变）

| 因素 | 现实机制 | 影响力 |
|---|---|---|
| **马体重（馬体重）** | 每场赛前约 70 分钟称重公布。**变化 20 磅以内=状态接近上场；超过则须与「跑入前三时的标准体重」比对** | ★★★ |
| **疲劳 / 休养间隔** | 出赛间隔、放牧质量决定状态 | ★★☆ |
| **斗志 / 状态** | 亮相圈动态：肌肉结实、双目有神=佳；急躁出汗、多次起飞脚=不佳 | ★★ |
| **试闸表现** | 入闸与出闸熟练度 | ★★ |
| **增重 / 减重** | 「马体变化」本身就是赛前最重要的公开情报之一 | ★★★ |

### 1.3 竞赛条件层（规则，赛前可知）

| 因素 | 现实机制 | 影响力 |
|---|---|---|
| **负磅 / 斤量** | 三种制度：定量（按年龄 Weight For Age）/ 别定（年龄+性别+收入+胜场）/ 让磅（按实力人为加减）。<br>JRA 实例：3 岁 55kg、4 岁以上 57kg、**牝馬 -2kg**、南半球产 -1kg；**赢 G1 加 2kg、G2 加 1kg** | ★★★ |
| **枠順 / 闸位** | 转向赛道短途：**内侧闸位占优**（到第一个弯的距离最短）。<br>左回场地内档有利 / 右回场地高号码档有利；**大场数时效果放大**；<br>「跑法 × 闸位」需匹配：放头马配内档、后上马配中档 | ★★★ |
| **骑手** | 骑师实力（胜出率/三甲率）、换骑手、**是否曾策骑该马入前三**、减量（见习骑师）；<br>本场是「该马首次配此骑手」也是情报点 | ★★★ |
| **练马师** | 在该场地/该距离的成绩 | ★★ |
| **班次** | 升降班直接影响对手强度与负磅 | ★★ |
| **马具 / 蹄铁** | ブリンカー（遮眼罩）改善集中力；蹄铁与矫正具影响发挥 | ★☆ |

### 1.4 环境与赛道层（场地）

| 因素 | 现实机制 | 影响力 |
|---|---|---|
| **距离** | 最核心的分类变量（短途/一哩/中距离/长距离） | ★★★ |
| **场地状态（馬場状態）** | 良 / 稍重 / 重 / 不良。**烂地会「拉长」有效距离**：快跑能撑一哩的马，软地上可能撑不住 | ★★★ |
| **回向** | 左回 / 右回，与马匹适性直接冲突时打折 | ★★☆ |
| **直线长度（直線の長さ）** | 东京 525m vs 中山 310m。**短直道严重压制差し/追込**，长直道则放大末脚价值 | ★★★ |
| **小回り** | 转弯急、直道短的场地（如 Chester）**强烈有利于前速马**，后上几乎无解 | ★★☆ |
| **坡度（坂）** | 中山/阪神的急坂消耗耐力，考验力量 | ★★ |
| **天气（天候）** | 雨、**向风**（终直逆风显著增加难度） | ★★ |
| **路面磨损 / 内有利↔外有利的翻转** | 同一场地随开催进行，**内栏被反复踩踏而变差**，「内有利」会在当天中途翻转为「外差し有利」。<br>**这是当天最重要的临场情报之一** | ★★★ |

### 1.5 动态博弈层（展开 —— 现实中最被低估的一层）

| 因素 | 现实机制 | 影响力 |
|---|---|---|
| **步速档位（ペース）** | 3F / 4F 分段判定 ハイペース / 平均 / スローペース。**「看懂了步速，一半的功课就做完了」** | ★★★ |
| **展开 / 跑法构成（展開）** | 三种形态：<br>・**Lone Speed** 单骑领放 → 前速马偷走比赛，赔率长期被低估<br>・**Contested Pace** 多马争抢 → 互相消耗，后上型捡漏<br>・**No Speed** 全场无前速 → 被迫领放者反而易赢 | ★★★ |
| **上がり3ハロン** | 日本赛马的头号指标。**步速与上がり是「天平的两端」**：慢步速 → 变成末脚对决；<br>快步速却上がり低 = 状态或能力有问题的信号 | ★★★ |
| **市场对展开的系统性错误定价** | 业界共识：**「betting market almost never prices pace correctly」** —— 赔率反映实力，但很少反映展开 | ★★★ |
| **被包夹 / 包まれ** | 被封在内栏无路可走，被迫等待或强行突破 | ★★☆ |
| **道次选择与抢位的代价** | 领放者承受全部风阻，跟跑者借尾流省力（约 1~2 马身） | ★★☆ |
| **场地几何** | 弯道半径、起跑点到第一个弯的距离共同决定闸位价值 | ★★ |

## 2. 游戏当前已实现的机制（对照 `sim.js`）

### 2.1 做得好的部分（保留，勿动）

| # | 机制 | 代码位置 |
|---|---|---|
| 1 | 五阶段配速划分（出闸/序盘/中盘/后盘/终盘 = 5%/27%/30%/8%/30%） | `PHASE_DEFS` |
| 2 | 跑法系数（逃/先/差/追 × 五阶段，形状正确：早期 逃>先>差>追，末段反序且取负） | `STYLE_COEF` |
| 3 | 三段式体力：耐力池 → 毅力池 → 失速 | `H.stage` |

### 2.2 存在但薄弱 / 名存实亡的部分

| # | 机制 | 现状 |
|---|---|---|
| A | **闸位 / 内栏优势** | `TRACK_WIDTH` 已从 20 收窄到 11，注释明说「收窄后可以恢复真实的几何差异」，<br>但 `step` 里仍写着「让各道等效等长」——**注释与实现自相矛盾**。<br>实际 `laneRatio` 被 clamp 在 0.90~1.10，且**起跑时 t 只在 1.0~5.0 之间**（`1.0 + rng()*4`），<br>即整个马群挤在 11m 赛道的**内侧一半**，外侧从未被使用 → **真正的闸位展开根本不可能出现** |
| B | **智力** | 只参与每周训练效率，不进入比赛。这一设计本身合理，但需在策划案中明确说明 |
| C | **年龄 / 性别** | 生成后**完全不参与比赛计算**（无斤量差、无成熟度差） |
| D | **血统力** | 单一标量，只影响市场评分与繁殖，**不影响距离适性 / 泥地适性** |
| E | **距离适性** | 由「耐力 = 可跑距离」承担。逻辑自洽，但只回答「**能不能跑完**」，<br>没有回答「**在哪个区间表现最好**」（现实是有一个 optimal sweet spot） |
| F | **骑手** | 只有 4 档速度加成，**没有减量、没有换骑手、没有「骑手×马」配合** |
| G | **斗志** | 只做 ±5% 属性修正，**不产生行为异常**（现实里气性差的马会抢口、会不按跑法走） |

| # | 缺失项 | 备注 |
|---|---|---|

| 6 | **气性（temperament）** | 没有抢口/失控机制 |
| 7 | **体质 / 健康（赛内）** | 生涯模式有伤病与休养，但**比赛中不体现** |

| 12 | **市场对步速的误判** | 市场模型里**没有 pace 变量** → 缺掉最大的套利空间 |
| 13 | **直线长度** | 直道长度由距离推导，无独立维度（无「短直道压制后上」） |

| 15 | **天气 / 风向** | 只有场地状态，无雨无风 |
| 16 | **路面磨损与内外有利翻转** | 完全没有（现实中最有价值的临场情报之一） |
| 17 | **赛前信息公开面板** | 没有枠順表、没有马体重、没有前走上がり —— **而这些恰是情报系统最该有误差的地方** |

## 4. 三个关键落差（展开）

### 4.1 步速与上がり3ハロン缺位 —— 核心玩法的最大机会缺口 🔴

本项目的卖点是「**信息差博弈**」：玩家用有误差的情报，在市场里寻找被错价的价值。

而现实世界**最大的市场错价来源就是「展开」**。业界共识是：
赔率充分反映了马匹实力，但**几乎从不正确反映步速与展开**。

但当前市场模型（`MARKET`）的六个公开信号是：战绩、骑手、血统、年龄、适性、体格 ——
**没有任何一个与步速/展开相关**。也就是说：

- 现实中「看懂步速就能赚钱」这条最重要的技术，在本作里**没有对应的对象可看**；
- 市场也没有犯「看错步速」这个错误，于是玩家也就无从利用。

**结论：补上「步速档位 + 上がり3ハロン」不是数值拟真的锦上添花，而是直接扩大核心玩法的维度。**
这是本报告里性价比最高的一项。

### 4.2 竞赛条件层整体缺失（斤量 / 枠順 / 马体重） 🔴

现实中这四项每天都在决定赛果，且**全部是「赛前公开、但有解读空间」的信息** ——
这正好是情报系统最理想的载体：

| 项 | 现实规则 | 若落地到本作 |
|---|---|---|
| **斤量** | 3岁 55 / 古馬 57 / 牝馬 -2 / G1 胜者 +2 | 一个直接的速度惩罚，且**使「牝馬」「年龄」终于有意义** |
| **枠順** | 内档有利（急弯短途尤甚），跑法×档位需匹配 | 把 `t` 扩展到全幅 11m，显式闸位号，恢复真实的 lane 几何 |
| **马体重** | 赛前 70 分钟公布，±20 磅判据 | 逐场随机波动 + **公开但可被误读的情报** |
| **班次加磅** | 赢 G1 加 2kg | 让「连胜溢价」有真实依据 |

补上这一层，可以同时解决三个问题：
① 数值更真实；② `年龄`/`性别` 从死数据变成活变量；③ 情报系统多了四个有误差的对象。

### 4.3 距离适性只有「能不能跑完」，没有「甜区」 🟠

现在的模型：`耐力 70 → 2240m`，跑得完就跑，跑不完就崩。
这正确回答了「**这匹马跑不跑得完 2400m**」，但没有回答「**这匹马在 1600m 还是 2400m 更可能赢**」。

现实中后者由**血统**决定（父系平均胜出距离、母父的影响），且存在一个**最适区间**：
- 偏短：爆发型，1600m 有威胁，2400m 会「撞墙」
- 偏长：伸展型，1600m 显得迟钝，2400m 才如鱼得水

**建议**：把「血统力」这个单一标量拆成 `适性距离中心 + 适性宽度` 两个遗传量，
再让「偏离甜区」产生一个乘性惩罚。这样：
- 距离适性终于**由血统遗传**（符合现实，也让繁殖系统有意义）
- 繁殖不再只产出「数值更高」的马，而是产出「适性不同」的马 —— **玩法深度大幅提升**

## 8. 阶段一详细设计：步速系统（pace）

### 8.1 诊断 —— 为什么现有的 `paceContest` 效果有限

现有实现（`sim.js` L1065-1067 / L1085-1087 / L1225-1226）：

```js
// 争抢强度
let contesters = 0;
for (const H of act) if (H.style === '逃') contesters++;
race.paceContest = Math.max(0, Math.min(RACE_F.paceContestCap, contesters) - 1);
// 速度端（序盘/中盘）
if (race.paceContest > 0 && (ph.key === 'open' || ph.key === 'mid'))
  runCoef += race.paceContest * RACE_F.paceContestCoef;      // +0.012/匹
// 油耗端（序盘/中盘）
const contestDrain = 1 + race.paceContest * RACE_F.paceContestDrain;   // +14%/匹
```

存在两个结构性问题：

**问题一：速度加成是「全场平摊」的，不分跑法。**
现实中步速由领放者设定，它只把**靠前争抢的马**拖着走；后上型仍按自己的节奏跑，
快步速对它的意义是「差距被拉开」，而不是「被拖着提速」。
现在的写法对逃、先、差、追一视同仁，等于抹掉了「展开」最关键的那层差异。

**问题二（更致命）：油耗端被归一化抵消了。**

```js
const effort = clamp(H.v / race.avgV, 0.6, 1.6);   // ← 相对全场均速
const effortDrain = Math.pow(effort, RACE_F.effortExp);
```

步速抬高全场速度时，**分子（`H.v`）与分母（`race.avgV`）同时变大**，`effort` 几乎不变
→ `effortDrain` 也几乎不变 → **步速在油耗端的效应被数学抵消了**。

结果：`paceContest` 只剩一个静态的 `1.14^n` 消耗惩罚，**没有真正改变体力分配**。
这就是 `race-drama` 报出「71% 场次半程领先者即冠军」的根因——
比赛中段的节奏博弈看似存在，实则没有传导到末段的实力重排。

### 8.2 设计 —— 拆成「判定 → 三个作用点 → 产出」

**① 采集：争抢强度（不是简单数逃马）**

```js
// 想抢领放的意愿 = 逃(全部) + 先(部分)
// 用斗心/气性调制"敢不敢抢"，而不是只看数量
let want = 0;
for (const H of act) {
  if (H.style === '逃') want += 1.00 * (0.6 + 0.4 * (H.morale / 100));
  else if (H.style === '先') want += 0.35 * (0.6 + 0.4 * (H.morale / 100));
}
// 场数放大：马越多越容易形成争抢
const fieldFactor = 1 + (act.length - 8) * 0.02;
const paceStrength = (want / 1.15) * fieldFactor;   // 1.0 = 标准节奏
```

**② 判定：步速档位（可播报、可被市场误判）**

```js
const paceLevel = paceStrength < 0.85 ? 'スロー'
                : paceStrength > 1.15 ? 'ハイ' : '平均';
const paceCoef  = 1 + 0.045 * (paceStrength - 1);   // 对前段速度的拉动幅度
```

**③ 拉动前部速度 —— 按跑法衰减（解决「问题一」）**

```js
// 越靠前、越想抢的马，被步速拉动越多；后上型几乎不受影响
const PACE_PULL = { '逃': 1.00, '先': 0.60, '差': 0.20, '追': 0.10 };
if (ph.key === 'break' || ph.key === 'open' || ph.key === 'mid')
  runCoef += (paceCoef - 1) * PACE_PULL[H.style];
```

**④ 节奏税 —— 只抽「承受步速」的马（解决「问题二」，这是核心）**

不再依赖被归一化抵消的 `effortDrain`，而是加一个**不参与归一化**的独立项：

```js
// 承受份额 × 步速超出量。单骑领放时 paceStrength < 1 → 税额为 0
const paceTax = 1 + 0.35 * PACE_PULL[H.style] * Math.max(0, paceStrength - 1);
drain *= paceTax;
```

这一项的关键性质：**它作用于绝对量，不与 `avgV` 相除，所以不会被抵消。**
同时因为乘了 `PACE_PULL`，快步速的代价几乎全部落在逃马与先行马身上，
后上型的油耗基本不变 —— 这正是现实中「快节奏烧掉前速马、后上型捡漏」的机制。

**⑤ 上报为公开情报（接情报系统）**

- 本场步速档位（スロー/平均/ハイ）
- 赛后揭穿的 **上がり3ハロン**（末段 600m 用时）—— 日本赛马的头号指标
- 二者构成「天平两端」：慢步速 → 上がり快是常态；快步速还能跑出快上がり，才是真本事

**⑥ 产出：市场误判 → 套利空间**

给市场一个**看得见、但系统性低估**的步速信号：

```js
// 市场看得见步速（公开），但它只做了打折处理（damped adjustment）
// 真效应 ×0.4 → 剩下的 0.6 就是玩家能吃到的错价
marketPaceAdjust = 1 + 0.4 * (truePaceEffect - 1);
```

于是形成本项目核心玩法所需要的缺口：
- **单骑领放**：全场不抢 → 领放者省油 → 现实中容易被「偷走比赛」，但市场只轻微上调它
- **多马争抢**：前速马集体烧油 → 后上型受益，但市场只轻微下调前速马

### 8.3 三个现实形态如何自动涌现

| | スロー（单骑领放） | ハイ（多马争抢） | 无前速 |
|---|---|---|---|
| `paceStrength` | < 1 → **税额 0** | > 1 → **重税** | 低 |
| 领放者 | 省油、控制节奏 | 烧油、末段崩溃 | 被迫领放但节奏慢 |
| 跟跑者 | 借尾流但节奏慢 | 借尾流、相对受益 | 措手不及 |
| 后上型 | 追不上（对手有余力） | **捡漏，高赔率** | 无步速可借，反而吃亏 |
| 典型胜者 | 前速马 | 差し / 追込 | 被迫领放者 |

**三种形态全部由公式自动产生，不需要为它们分别写分支。**

### 8.4 代码落点

| 位置 | 改动 |
|---|---|
| `RACE_F` | 新增 `pacePull` / `paceTaxK` / `paceSpeedK` 三个旋钮 |
| `step()` 第 1 步 | `paceContest` 计数升级为 `paceStrength`（含斗心与场数）；速度端改按跑法衰减 |
| `step()` 第 3 步 | 新增 `paceTax` 乘入 `drain`（不复用被归一化的 `effortDrain`） |
| `step()` 第 5 步 | 记录 `H.final3f`（末段 600m 用时）；赛后写入 `race.paceLevel` |
| `marketEntryScore` | 新增 damped 的步速调整项 |
| `snapshot()` | 输出 `paceLevel` / `final3f` 供 UI 与情报系统读取 |
| `tests/race-drama.js` | 半程定冠军率应从 71% 向 ~50% 收敛 |
| 新增 `tests/pace.js` | 验证三种形态、步速档位分布、上がり 与步速的负相关 |

### 8.5 风险与取舍

- **风险一：过度修正**。`paceTaxK` 若过大，会变成「逃马必输」。
  缓解：以 逃/先/差/追 各 25% 为收敛目标，用 `style-by-distance` 跨距离校验。
- **风险二：与既有 `draftSave/leadCost` 叠加**。两者都在惩罚领放，
  需先测出当前领放惩罚的实际量级，再决定 `paceTaxK` 的起点，避免「双重惩罚」。
- **取舍**：不动 `effortExp` 归一化本身。
  它的存在是为了避免「掉速→跑更久→耗更多→掉更快」的死亡螺旋（代码注释有记录），
  所以正确做法是**旁路新增一个绝对项**，而不是修改它。

### 8.6 建议的验收标准

1. `race-drama` 半程领先者即冠军的比例 **≤ 60%**（现 71%）
2. `style-by-distance` 各距离极差 **≤ 25%**（现 1200m 达 75%）
3. `market` 相关系数 **≥ 0.25**（现 0.102），且出现「上帝视角 ROI 下降、市场逆势 ROI 保持 > 1」
4. 新增 `tests/pace.js` 三项断言全绿

## 9. 阶段一实施结果（2026-10-01）

新增验收台 **`tests/realism.js`**，把「贴近现实」拆成三条可量化指标。
用法：`node tests/realism.js [每档场次] [悬念场次]`（默认 50 / 150）。

### 9.1 过程中查出并修复的真实缺陷

都不是「调参」，而是实现错误。按影响排序：

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | `STYLE_COEF` **积分方向反了**（差 1.05757 > 追 1.05599 > 先 1.05687 > 逃 1.05185） | 1200m 出现「追 74% / 逃 0%」的完全反向结果 |
| 2 | **回向适性系数被无条件乘进全程**（含直道） | 生成器给约 11% 的马分配不符回向，造成全程 10% 降速 |
| 3 | **内外道几何符号写反**（`(R+t)/R`），且注释写着「各道等效等长」自相矛盾 | 外道白拿最多 3.6% 速度，而后上型恰好跑外道 |
| 4 | **失速无限崩溃**：`H.v·0.95^dt` 一路衰减到 `STALL_SPEED=2 m/s` | 末位被拉到 **153 马身**（约 367m） |
| 5 | **爆发力项在毅力阶段直接归零** | 体力耗尽的瞬间产生速度断崖，是马身差距失控主因之一 |
| 6 | **加速项构成正反馈**：`accel ∝ (1−stRatio)`（已消耗比例） | 「跑得越快→耗得越多→末段加速越大」，与注释声称的「省下的油变现」相反；实测让逃马在 1200m 拿到 80% 胜率（而系数优势仅 0.31%） |
| 7 | 疲劳惩罚过重（85~100 → 0.6，>100 → 0.3） | 单项即可贡献 8~40% 速度差 |
| 8 | 碰撞减速下限 0.5 | 被撞一下掉一半速度 |
| 9 | 跑法模板把**耐力与速度也按跑法分化**（追 耐力仅 40~65 ≈ 1664m） | 后上型在马厩里就跑不完 2000m，马群裂成「两匹能跑完 + 六匹崩盘」 |
| 10 | `baseSpeed` 斜率 0.045 | 同场 level 跨度 8~10 点 → 基速差 4.1%，而现实同班次只有 2~3% |

### 9.2 新增功能

- **步速系统**：`paceStrengthOf()` 只吃公开信息（跑法 + 斗心），在 `createRace` 判定一次并**冻结**
  （每帧重算会被赛末减员稀释，实测 2 匹逃马的场次会被算成 0.67）
- **`pacePull` + `paceSpeedK`**：按跑法衰减地拉动前段速度（逃 1.0 / 先 0.6 / 差 0.2 / 追 0.1）
- **`paceTax`**：**不参与归一化**的绝对项。旧的 `contestDrain` 乘在 `effortDrain` 上，
  而 `effort = v / avgV` 会在步速抬高全场速度时分子分母同时变大、**效应被数学抵消**
- **上がり3ハロン**：记录冲过终点前 600m 的时刻，完赛时相减；`snapshot` 已暴露 `final3f`
- **市场误判 pace**：`marketPaceDamp = 0.40` —— 市场看得见节奏，但只兑现真效应的 40%

### 9.4 尚未解决：马身差距

已定位到它**不是能力跨度问题**：把 8 匹马设成**完全同水平**时，
