# 当前比赛引擎系统机制审计（2026-10-02）

审计对象：提交 `582ce9046dd8552d950d0296e8500a8234388eff`，引擎版本 `v2026.10.02.2`。本文件只记录当前机制、简化与可检验假设；本轮不修改引擎，不调整参数，不预先认定哪项机制应先重做。代码行号对应该冻结提交。

本文件已接入本轮真实赛事的正式分流主组评估结果，见第8节；独立随机流432场矩阵及交通制动复现见第9节。第1–7节的“指标特征”仍是区分机制的测量建议，并非每项都已观测或识别原因。旧随机流耦合组仅作敏感性对照。

## 判读原则

- **已有**：能在比赛执行或赛前输入中找到明确的因果路径。
- **简化**：已表达方向或约束，但函数、参数或状态维度受限。
- **缺失**：在当前比赛状态和执行路径中没有对应变量或规则；不等于该机制已证明对当前误差重要。
- 一个平均赛时或着差可被能力分布、路线、出力、交通等多种因素共同改变。先测量不同条件下的误差形状，再用受控实验区分候选原因。
- 工程守恒、有限速度、正常完赛和机制方向通过，不等于现实用时、逐段曲线或个体表现已拟合。
- 比赛首马每200米用时是各路标最早通过时间，领跑者可以变化；冠军最后600米是同一冠军自身用时。比较时必须保持口径一致。
- 当前共有 **17个布局：14个官方尺寸约束布局和3个抽象布局**。不能把17个都称为官方布局。

历史接口不代表当前执行机制：五阶段 `PHASE_DEFS` 只为兼容保留，跑法系数与骑手直接速度奖励已中性化；旧 `GROUND_RANGE_COEF/rangeCoef` 不再负责比赛耗能。当前地面成本要看 `powerTerms`，不能从旧接口或旧评估文档反推。`collisionCoef/collisionIntensity/stallTimer` 等保留字段也不证明已经有接触动力学。
