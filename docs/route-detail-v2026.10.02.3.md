## 空间路径与物理共用

每个弯使用五次Bezier参考曲线，两端控制点共线，端点曲率为零；参考路径、单位切向、局部曲率由同一弧长位置读取。整圈两条直线与两段变曲率弯闭合，端点切向连续。Bezier控制形状不是赛道测绘，不能据此断言真实各处半径已经拟合。

离散查表的位置、切向、曲率及路径度量通过同一局部五次Hermite曲线获得，避免位置用直线插值、法向另外插值而产生不同的空间速度。表中插入精确直弯结点，端点位置、切向与曲率共享，避免跨接点和不同求值模式间的微小坐标跳变。约0.5米空间查表只用于路径求值，不是按比赛距离设置的运动阶段。

横向坐标`t`表示到内栏的距离。车道位置是参考路径沿法向偏移`t-referenceLane`。当前车道曲率为`k/(1+k*(t-referenceLane))`，纵向进度系数为该偏移曲线度量的倒数；所以更外车道自然付出额外路程，而非获得独立跑法惩罚。骑乘预测、真实运动曲率上限、弯道做功和画面都应调用这些相同接口。

保留`geo.S/B/R/referenceR`作为旧尺度兼容字段；它们不能用于新路线的局部物理半径。调用者使用：

```js
trackPoint(s, t, geo, direction)       // 当前路线的真实代理空间位置
trackTangent(s, t, geo, direction)     // 单位切向 {x,y}
kAt(s, geo)                          // 参考车道曲率
laneCurvatureAt(s, t, geo)            // 当前车道曲率，直道为0
laneProgressCoef(s, t, geo)           // 实际纵向路程 → 参考比赛进度
laneArcDistance(s0, s1, t, geo)       // 固定车道的有符号实际路径弧长
laneAdvance(s, distance, t, geo)      // 按实际弧长反解比赛进度
laneArcBreakpoints(s0, s1, geo)       // 区间内路径求值结点，升序且不含端点
trackWidthAt(s, geo)                  // 本轮等于geo.width
```

`laneArcDistance`对参考曲线的真实导数长度分段积分，并使用平行曲线的精确关系`L(t)=L(reference)+(t-referenceLane)*累计转角`。`laneAdvance`反解同一积分；正负路程、跨直弯接点、引入线合流和跨圈使用相同规则。抽象圆弧按直线/圆弧精确分段。真实运动、未来制动轨迹和骑乘完赛预测共用这两个接口，消除只取起点或中点曲率时，步长和接点位置改变实际行进路程的问题。参考曲线查表的名义进度不是严格弧长参数，因此`laneProgressCoef`包含真实`|dr/ds|`，参考车道值允许有微小数值偏离1。

积分累计表按布局缓存；局部积分使用五点Gauss求积，反解使用带区间保护的Newton迭代。`laneArcBreakpoints`覆盖真实Hermite单元、直弯接点及引入线结点，但单元内曲率不是线性或必然单调，交通极值域不能只把结点端点当作全区间曲率极值。

骑手预算的每个单元使用相同接口计算实际总弧长；单元内部做功求积的位置采用进度线性插值，属于有独立密集积分核对的预测近似。实际运动和交通制动路径逐次反解实际弧长，不使用这项预测近似。

几何提供保守进度系数上界，用于证明远离的两马无需完整制动域求根。每个五次Hermite单元转换为Bezier控制点：四次速度控制向量的正切投影下界约束真实速度范数，三次加速度控制向量范数上界约束曲率；覆盖闭合圈、引入线和合法横向位置。若不能证明正的度量下界，则返回Infinity，禁用此项早退。这个界不靠抽样估计，也不修改实际路线。

`geo.displaySegments`给出完整闭合圈及可选引入线的比赛进度区间。各段`from/to`可直接用于`trackPoint`采样；`kind='loop'`标记闭合圈，`kind='chute'`标记独立发走线。引入线之后按同一圈位置继续运动；起步时不会把不同路线上的空间位置误当作在旧半圆中。

## 机制验证

执行`node tests/route-detail-v9.js`。该脚本覆盖14布局、六个基准路线、独立引入线连接、左右方向、参考与偏移车道。它检查闭合、首弯/终直约束、切向连续、全圈累计转角、坡积分、坡锚点、真实空间弧长与比赛进度，以及局部空间导数和`laneProgressCoef`的一致性。

截至本轮执行，21个布局/起跑路线的226748项断言通过：参考车道全圈实际空间弧长最大误差0.000071米，内外车道弧长差相对`2πΔt`最大误差0.0000079米，直弯接点两侧切向差最大`5.7e-7`。30位置×2车道/布局的空间导数与进度系数相乘相对1误差均小于0.025%。新增逐毫米坐标弧长与积分核对最大误差`6.1e-12`米，弧长反解/正反运动/拆步组合误差均小于`1e-9`米；单步与191个小步跨抽象直弯接点及真实路线接点的结果相符。这些是数值自洽精度，**不是复刻真实赛道的测绘误差**。

本文件只记录路线机制验证。完整比赛时间、速度、交通、末段及胜率的版本对照由本轮综合验收报告给出，不能用几何测试替代比赛现实拟合评估。

最后复查发现，第一弯道接背面直道时，极小浮点误差可让`atan2`从+π跳到−π。车道弧长使用累计转角，这个2π跳变会把纳米级进度算成上百米。修复按当前弯段的预期累计方向展开角度，并保留直道端点的明确角度；弧长逆解和交通未来轨迹共用修复。

[微边界回归](route-heading-junction-v9.json)在最终数值源`3b837b`上覆盖21布局/起点路线：2220项航向检查、17244项密集浮点边界检查、4068项实际弧长检查及7560项推进反解。旧开发源`44b09f`在6个布局复现785项异常，最大推进误差146.398米；最终数值源0项异常，最大推进误差9.69×10⁻¹⁰米。边界采样仍是有限数值覆盖，不是全部浮点状态的形式证明。以上226748项常规路线断言也已在遥测修复前的生产源码`96d84a28`重新通过。

最终生产源码`51caabc1`只在该生产版之上统一了跟车余量记录谓词，路线几何、弧长及运动求解保持相同。[全源逆补丁证明](source-snapshot-equivalence-v9.json)精确逆去两行旧档案入口及一处遥测修复后恢复整个`3b837b`数值快照；[4410帧边界配对](traffic-slack-boundary-v9.json)的实际运动、供能与完赛结果完全相同。上述几何数据保留实际受测源码，不改标为最终源码重跑。
