# G1 预测窗口的资格语义

应把共同预测窗口视作合成人群的匹配分布假设，而不是 G1 参赛资格。当前 `forecast.seconds>=fast` 相当于“比高端参考马更快就不合格”，与开放级赛事吸引、优先接纳高水平马的方向相反。JRA 的说明中，部分古马 G1 对已报名且达到评级门槛的评级前十位提供优先出赛，而分级说明把 G1 放在开放级竞争层级。[JRA 出赛顺序说明](https://www.jra.go.jp/keiba/tokubetsu/mikata.html)、[JRA 赛事分级](https://www.jra.go.jp/keiba/rules/class.html)。

这是对规则与模型的推论：G1 的实际参赛仍受年龄、性别、报名、数量、资格路径和赛程等约束；上述来源并没有提供模拟属性值的门槛，也不能直接把本引擎预测秒数当作现实评级。

当前冻结源 `1ca77ab...` 的一个赛前反例：32 位固定生成 G1 中心能力候选，加一位保存属性合法、level 97 的更强候选；東京芝 A 2400 m、健康、统一负磅。窗口为 138.0483–140.6303 s，该强候选预测 137.4766 s，预测可支付；其余有 13 位符合窗口，选 8 位无需 fallback，于是这位更强马被硬性标记“不合格”并必然排除。没有真实比赛步进，也没有读取未来赛果。输入、完整候选与诊断保存在 JSON 中。

这个例子只证明上边界的语义问题，不估计真实赛场中发生比例。当前随机单场生成的候选能力已集中在窗口附近；更明显的影响可能出现在持久化 roster 中已有精英马、训练或繁育产生更强马之后。玩家主动报名的保留身份不受同样筛选约束，还可能形成玩家与对手的不对称。

下轮建议将三件事分开：

1. 实际 eligibility 使用明确的年龄、性别、战绩/开放级、报名、冷却等赛事条件；不会因“预测太快”丧失资格。
2. 距离×能力联合预测用于候选参赛意愿或合成阵容的分布匹配。命名为 matching/nomination，不报告为真实资格；强尾保留非零支持。
3. 数量过多时，再按公开评级/成绩、优先权或明确抽签规则选择，避免把“最接近参考秒数”当成优先级。顶级 G1 的高能力尾不应因比中心值更强而被惩罚；若用权重，必须说明生成假设和其独立依据。

仅去掉硬上界、仍保留从窄 level 范围生成候选，并不能自动产生现实的精英尾；把硬窗改成很尖锐的软窗也可能只是把同一问题隐藏起来。验证应检查报名资格对更强表型的方向、旧 roster 精英是否能报名、候选与选中分布的两侧支持、fallback 和玩家/对手对称性，而不是只看场尾是否变小。

上面的反例描述冻结的旧源 1ca77；相应旧实现诊断保留，不应强迫新实现继续拒绝强马。

随后按主任务要求交付的 [增量补丁](../tests/fixtures/race-cohort-admission-v11.patch) 去掉 fast 侧拒绝与补位惩罚。可支付且不慢于 slow 参考的候选，包括比 fast 更强者，都有均匀无放回匹配机会；不按隐藏表现额外优先强马，也不指定冠军。参考 fast 保留作解释和诊断。`eligibilityScope` 明确资格来自调用方，`fastIsNotAdmissionCeiling` 明确强者不会因参考上限被拒绝。

原 level±2 生成范围暂保留作类别代理，没有扩展成未经证据支持的人才分布。已保存马的能力、生理和行为保持稳定，旧 roster 的极强马只要符合上游条件也有报名支持。同时修复上游 `winsMax:0` 原先因逻辑或运算变成99的明确错误；有胜场的马不能借此进入未胜利赛。

聚焦回归在内存组合源 9f8cbe4 中通过：原来被拒绝的 137.4766 s 强马现在符合匹配，有正概率进入，均匀抽样也可选择普通马；不足补位时较弱不匹配者不会排在该强马之前。JSON 旧档的全97能力精英能经实际 `pickRosterField` 进入 G1，年龄、胜场和休息不符的复制马仍被资格层拒绝，生理迁移重载稳定。未胜利赛只保留零胜马，未传胜场上限时历史默认不变。正式完整17项仍等待最终生产冻结；不得把内存组合 hash 当成最终生产已验收。

本子任务未修改生产。运行 `node tests/cohort-admission-v11.js` 做补丁的三项聚焦检查；正式结果仍应把这版阵容标作代表性匹配样本，而非完整现实 G1 资格和报名意愿仿真。
