# 跟跑机会的分层检查 v11

原控制器每次考虑跟跑，都先执行两次完整的 60 Hz 前车约束预测：一次保持配速参照、一次跟跑后追赶。大量候选最终被拒绝，仍然支付了这两次预测的计算成本。

候选修正先复用已有粗步长参照，并以相同步长检查跟跑/追赶的目标、净耗能和自身路径。粗筛通过后，才执行原有的 60 Hz 参照和追赶复核。最终候选必须细预测可支付、达到追赶目标、净耗能更低且没有自身路径冲突，才能参加决策和提交动作。已提交序列的再观察复核继续使用 60 Hz。

粗筛是计算资源有限时的规划启发式。它可能漏掉细预测认为有利的动作；没有为它声称经过证明的误差范围或交通认证。实际运动、有限制动、跟车安全与能量结算函数均未修改。

`H.followOpportunity` 保存粗细结果、`fineChecked`、节能数据所用分辨率和 `rejectedReason`。实际统计另记粗筛次数、粗筛拒绝、细检查、细检查通过、细检查拒绝及拒绝原因。细检查通过但没有被选择的候选记为 `lower-score`，不提前兑现其节能收益。

## 构造检查

`follow-coarse-screen-focused-v11.json` 的 10 项检查通过。用明确标注的预测 stub 分别触发能量、目标、路径、净收益四种拒绝：粗拒绝不会执行细预测；粗通过而细拒绝不能提交跟跑；能提交的候选必须来自细检查。另有真实默认预测 API 和 300 帧固定控制执行的逐位等价检查。stub 检查只证明调度门槛，不作为现实拟合证据。

候选 fixture：`tests/fixtures/follow-coarse-screen-v11.js`，`applyFollowCoarseScreenPatch(source)`。测试原源 `d0fea99e162584783b93e64a25ceb47685ab90894140de5c63aea548f3d6b956`；候选 `50f77fdc68a5db53a6e660e8a4c5a0137d8303693988f646282c6bddedec75a1`。这两份测试源快照保持独立，后续集成源需另行验收。

## 真实场地条件下的配对初段

`follow-coarse-screen-partial-v11.json.gz` 使用校准任务 231126 的同一组 18 匹马、2400 米东京芝 A、良地、相同两个随机种子。两次实际执行都停在最后一匹马达到 600 米时；计 **2 次初段执行、0 场完整比赛**。其余 16 次是初段完成后的只读细预测查询，没有增加实际比赛执行。只读摘要与归档来源检查使用显式`.gz`输入，见[v11-gzip-reproduction.md](v11-gzip-reproduction.md)。

这一个初段样本 CPU 减少 29.43%，规划阶段细预测调用减少 98.44%。粗筛拒绝 63 次，其中目标 46、净节能 10、自身路径 7；仅 1 次需要细复核，细复核通过后因其他动作得分更高而未被选择。

记录的实际状态、运动与能量账本、交通、采样轨迹、工程结果与全部选择决策逐位一致；起步 200/400/600 米的领先者和全场中位用时差均为零。严格数据比较只排除了规划诊断计数，排除项已列在机器报告。粗筛拒绝次数的含义与旧版细筛拒绝次数不同，不能将它们当作物理差异。

## 已观察到的漏筛

按预定规则，对候选最早 8 个粗筛拒绝机会补做细预测，共 16 次查询。这 8 个机会没有细预测可行的跟跑动作。这个早期小样本没有覆盖全部 64 次机会。

全量配对诊断还保留了一例漏筛：h17 在 18.25 秒时，旧细预测显示净节能 `+0.000806`，新粗预测显示 `−0.000279`，因而被粗筛掉。旧控制器在同一实际状态下也选择等待，此次漏筛没有改变这个初段的实际动作。它明确证明不能把粗筛宣传为“不会漏掉有利动作”。

本结果支持集成后继续做完整比赛验证。距离、阵容、赛级和末段状态变化可能改变机会分布，整场加速比例、跟跑使用情况和现实拟合指标都需要冻结最终源码后重新测量。
