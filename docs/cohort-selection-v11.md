实现由 [精确源片段 fixture](../tests/fixtures/race-cohort-v11.patch) 交给主任务顺序整合；本子任务没有直接写生产引擎或页面。机制验收数据见 [cohort-selection-v11.json](cohort-selection-v11.json)，运行 `node tests/cohort-selection-v11.js`。整合后脚本会直接测试已整合的生产源码，并将当前 SHA 写进结果，不能把整合前的内存组合结果重标为生产测试。

## 从稳定候选池报名，不按实际赛果筛选

`makeRaceCandidatePool(rng,{n,level,levelBand,tierKey,tierDef,idPrefix,entryOverrides})` 一次生成有稳定身份、能力、性格与持久化生理档案的候选。生成不读取距离或赛道；同种子、等级和池规模在不同距离得到同一候选池。`entryOverrides` 只覆盖 surface、special、斗志、疲劳、jockeyGrade、bodyMass、carriedWeight，在完整生成和档案物化之后、筛选之前应用，不跳过任何生成 RNG 消耗，不改能力或生理轴。

`raceEntryForecast(h,raceOptions)` 只克隆候选、构造统一参考车道的初始状态，调用同引擎的 `H.finishPlan`；不运行比赛步进、不读取已有 place/time/history/wins。它二分连续请求速度，保留在储备和瞬时功率约束内的最高可行请求，返回预测总时、供給、容量、上限和所需储备。距离作用于真实路线、运动成本和可支付的功率预算；没有固定距离适性速度倍率。

共享预测已经积分发走延迟，报名总时直接采用 `best.seconds`，不再额外加一次 startDelay。二分只对不可行需求提前结束，保留完整可行预测；没有可行结果才执行原 3 m/s fallback。独立成本对照确认入选身份、诊断和预测完全相同，积分步数减少约 66%–73%，详见 [成本对照](cohort-forecast-cost-v11.md)。

`selectRaceCohort(candidates,rng,{n,level,levelBand,tierKey,tierDef,race,entryOverrides})` 返回 `{horses,diagnostics}`。赛级上下界与原 `FIELD_LEVEL_SPAN` 定义参考能力水平；参考马在同一赛况下给出共同的预测时间参考。匹配要求可支付且预测不慢于 slow 参考端；fast 端只保留作代表性参照，**比 fast 更快的强马仍可匹配**。匹配候选均匀无放回报名，不选择“八匹最接近的分数”，也不指定冠军。候选不足时才按超出 slow 端的距离补位，较强马没有 fast 侧惩罚；`fallback` 与 `shortage` 明确记录。

这是尚未用独立实赛群体标定的一版合成阵容匹配假设。参考范围不是由现实首末差或目标胜率反推出来；匹配也不保证实际完赛密度、节奏或骑手竞争已贴近现实。当前新生成候选仍使用原 level±2 的类别代理，没有声称它是现实人才分布。应分别核对上游赛事条件、生成候选分布、强尾支持、匹配比例和 fallback；这项机制不能单独替代群体数据标定。

年龄、胜场/开放级、出赛间隔等真正的赛事资格由调用方先筛选。诊断增加 `eligibilityScope` 和 `fastIsNotAdmissionCeiling:true`，说明既有 `eligible` 计数只表示预测匹配，不是官方资格。`pickRosterField` 同时修复 `winsMax:0` 被当作默认99的错误，未胜利赛不会因这个入口接纳已胜马；没有传最大胜场时原默认仍保留。机制与官方规则区别见 [资格语义审计](cohort-upper-window-review-v11.md)。

玩家 roster 公共入口也按现有赛程规则先筛资格：新马必须未出赛且零胜；未胜利必须零胜；一胜、二胜、三胜赛分别对应准确胜场；开放/G3/G2/G1 分别采用原赛程的最低4/2/3/4胜。原能力区间只保留最低准备度参考，最高能力不再成为报名天花板。选择前排除所有与玩家同 ID 的记录，避免本人作为对手重复入场；其它重复对手 ID 由选择器明确报错。持久能力、生理和已有性格不会重抽。通用 `abilityMax:0` 现在也按显式零处理。

`pickRosterField` 的赛况分支保留原请求数：如果要8匹、真正有资格的只有1匹，返回这1匹并记录 `requested:8, selected:1, shortage:7`，不会把需求缩成1来掩盖不足，也不把不合资格的马补进去。旧无赛况接口仍保留原选择形状。以上入口问题的旧源码失败与修复后通过记录见 [玩家资格与身份回归](cohort-player-entry-v11.json)，运行 `node tests/cohort-player-entry-v11.js`；这里没有实际比赛步进。

## 调用与兼容

- `makeField` 无赛况时仍返回原 n 匹数组、h1…hn 和指定玩家位置。历史 `strongIndex` 只保留身份兼容作用；`makeHorse` 的 strong/weak 选项不再加减能力点。
- `makeField` 有 `race` 或 `length/dist` 时生成 4n 候选，再按实际赛况报名。默认玩家候选身份保留在阵容中，改变距离不会换玩家能力或生理；玩家的主动参赛不受对手报名筛选控制。`playerIndex:-1` 明确生成全 AI 阵容。
- `field.cohort` 是非枚举元数据，JSON 数组不会自动保存它。正式报告须另存诊断，包含共同窗口、候选/符合条件/补位/不足数量和每匹预测。马个体档案原有字段照常保存，没有新增必需存档字段。
- 旧生涯 `makeCareerRaceField` 增加可选第4参数赛况；`raceOptionsFor`、瞩目赛事都会传入实际距离/场地。已有持久 roster 先按年龄、胜场、能力、间隔筛选，再共享条件报名；赛程、每周 AI、玩家 roster 选项全部传入赛况，原马属性与生理不会重新生成。
- 页面单场只在 `genField` 随机新建阵容时传入 `singleRaceOptions()`。用户编辑现有马、切换距离时，不自动重抽或替换已有个体。
- 新马/缺失档案的前进意图由与出闸/爆发能力独立的温和 Beta(2,2) 全区间先验产生，使用相同的一次 RNG 抽样；已保存 behavior 保持原值。先天偏好通过可达位置竞争作用，不给任何跑法物理加成。抽样和旧档保留对照见 [意图审计](behavior-intent-review-v11.md)。

## 消除等属性干预的 latent 重采样混杂

[新诊断 helper](../tests/helpers/race-cohort-v11.js) 导出 `fieldFor(job,S)`。它先完整生成并选择同一阵容、物化生理档案；`equal-ability-flat` 再把八项能力及历史诊断的其它属性设为70，`neutral` 再中和生理。健康平地/等能力平地同种子使用相同选中身份与原生理档案，行为也相同。等属性后不重新报名；否则选中集合的变化会构成额外干预。

外部 G1 诊断的健康、斗志、优秀骑手、480kg 和负磅通过 `entryOverrides` 在筛选前统一，避免先按随机疲劳/体重报名、选中后再改状态。旧 v9 `fieldFor`、旧档案、旧诊断完全未改，历史结果仍可以按原输入语义精确复现；新协议必须在报告中明确命名，不能混装进旧矩阵。
