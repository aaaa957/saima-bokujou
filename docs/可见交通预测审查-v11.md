# 可见交通预测审查 v11

本审查围绕预测和实际执行的跟车安全约束、骑手观察信息、起跑外推与计算成本。功能源 `e1bd832dbe954407d9fa7c44a12aa535881d8e2ab46fee8cb6a234033ccdb56f` 与两项计算优化源 `d0fea99e162584783b93e64a25ceb47685ab90894140de5c63aea548f3d6b956` 分别保存；各报告记录其实际测试源，不把开发快照自动视为最终发布版。

## 机制检查

`followingConstraintSolver` 从实际执行中提取同一套有限制动轨迹、停止终点、响应余量、弧长几何和安全区间证明。实际执行与预测使用同一个函数；没有用前车目标速度、能量或生理状态来补齐预测。跟车请求速度上限也共用 `followingSpeedCap`。预测仍独立支付自身运动功、供氧、储备、疲劳和恢复。

`prediction-visible-traffic-v11.json` 的提取比较明确读取 `race-validation-v11-cohort-initial-training.json.source.js.gz` 中的提取前源 `1ca77ab4…`，并与当前源的固定控制构造回放比较。三种交通排列各 180 帧的实际物理状态和账本逐位相等。三种恒定可见前车运动下，预测与实际各 180 帧终点、做功和储备消耗的误差小于 `1e-7`。报告的 12 项检查还覆盖重复观察去重、最近前车/遮风、横移、隐藏属性 getter 守卫与终点跨步。

前车在本步跨过终点时仍参与本步约束，下一步排除。初始状态没有足够有限制动余量时，预测返回失败状态，并保留其有限制动运动结果；没有将位置退回、把速度直接截成零或声称完整交通认证。

## 起跑外推和规划不确定性

默认观察 API 保持测得速度/加速度的有界外推，便于明确固定控制的一致性检查。骑手另行传入 `opponentMotionPrior`，使用自身可支付配速和公开参考加速模型构成起跑假设。对手尚未出闸或仍明显加速时，这个假设避免把全部零速度对手预测为一直留在闸中；先验所假定的出闸等待和参考配速都在结果元数据中可见。对手个体起步延迟、属性、储备和计划均不读取。

`prediction-public-prior-v11.json` 的 7 项检查通过。明确给出公开先验时，构造零速度对手在 8 秒内推进 92.73 米；默认观察模型仍保持零速度。该数字只是构造假设的演示，不能当作真实起跑数据。释放等待尚未结束的步不会产生位移或 NaN；已稳定运动的对手不受这个先验影响。

自身与可见对手的逐步身体扫掠或跟车不可行仍否决候选。两名外推对手在别处相互碰撞，只记为 `opponentPathConflict`：实际对手可能相互回应，而一次单向外推无法知道这些回应。此诊断不会无条件否决自身清晰路线。控制器删除了另一套使用不同积分方法的近距离扫掠检查，全部候选统一使用预测器的可见轨迹与自身冲突结果。

预测保持 `trafficCertified=false`。对手未来的目标和同步交通回应没有被模拟出来。粗步长可用于候选评分，但不能宣称安全认证；有绝对追赶/路线目标的动作使用细步长复核。开发构造测试也保留了初始跟车余量不足时粗细步长判定不同的证据。

## 计算成本和保持结果的优化

`profile-visible-traffic-v11.json` 记录功能源上的计数。固定绑定前车的 10.8 秒预测有 648 步、17,758 次跟车查询，其中跟车函数占该构造样本约 89% 的计时。8 匹 AI 的前三秒则有 206 次预测和 108,759 对对手扫掠查询，跟车函数占比很小。两种工作负载的主要成本不同。

两项优化不改变计算结果：

- 对手相互冲突的最终布尔量一旦为真，就停止以后该诊断的重复双循环；自身冲突检查继续执行。
- 只有发现横向扫掠相交的前车时才创建跟车求解器；最大速度仍按原完整对手集合计算，排序和实际制动求解原样保留。

`prediction-peer-pair-cpu-v11.json` 有 12 组完整预测 JSON 的逐位相等证据，另有 4、8、18 匹 AI 各 180 帧全部比赛 JSON 的逐位相等证据。17 个对手已有互相冲突时，细步长构造预测中位计时从 46.4 降至 22.7 毫秒，粗步长从 7.65 降至 3.40 毫秒。无冲突场景收益较小。这是局部微基准，不能当作整场比赛的速度提升比例。CPU 时钟和操作系统调度也会影响计时。

另一项尝试在区间递归中加入额外负样本，保存于 `following-witness-cpu-v11.json`。它在这些构造回放中保持结果，却使绑定前车微基准变慢，因此没有用于生产。其最初脚本未将人为不可行起始状态归为期望失败，首次失败报告也保存在历史目录；修正后的配对测试确认两份源码都在同一步、以同一状态拒绝这些输入。

完整比赛的计算优化复放另记在 `traffic-cpu-full-replay-v11.json`。复用原校准样本不计为新增执行；只新增优化后的一场回放。比较仅排除实际墙钟和线程 CPU 两个执行计时字段，保留所有马匹、轨迹、指标和工程检查。

本审查证明的是工程一致性、观察边界和构造场景的行为。与现实比赛的数值拟合必须使用另行冻结的最终源、参数和真实参考赛例验证。
